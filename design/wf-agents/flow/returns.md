- Every field of a return must have a reader: another cell, or the item page, whose reader is the owner; otherwise it is
  removed. A field shown on the item page carries a mark, the compiler counts it as used, and the page shows by the
  mark. The check exists so that nothing unattended stays in a return, and a remark saying some view reads a field, to
  pass the check, would defeat it.

- A cell's output must solve the problem: what is not needed the agent says does not apply, with no fixed list of
  questions forcing it to fill all. Questions it cannot answer force nonsense, and that nonsense becomes what later
  steps act on.

- Every return can carry a one-way message to the owner: needing no answer, with the work going on, shown on the page as
  unread with its work, cell and round, in the owner's language. A helper line's inner findings do not go this way.
  Questions all block, and an agent that only wants to tell the owner something has no other channel; a field on the
  return interrupts no work, while a tool for sending would end the round, since running a tool is a return.

- An agent reports in its return what is wrong with the flow, by a standard written in the field's description, with no
  debugging cell or review afterwards, and this stays on in real use too, until it has nothing of value to report. The
  standard can go in the field without another model, and these reports improve the flow.

- Feedback on the flow's cells does not go to the project's architect; it stays in the system for the owner and the
  assistant. The flow is wf-agents' own matter, not the managed project's.
