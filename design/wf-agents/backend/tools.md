- agent 要查询数据库或运行工具时，靠返回来做：由引擎去运行，agent 再从上一轮接着往下走，从不在一轮中途进行。对模型来说，
  两者都是一次工具调用，context 里的内容一样，次数也一样，而在一轮中途查询每次约省三秒。

- 怎样查询写在工具里，数据库的整个结构不放进 agent 的 context：它超过 20K，非常昂贵。

- 数据库中的每次查找都通过一个通用的查询工具。每种查找一个工具的做法被放弃了：这类工具读的东西，通用查询和 git 也能读，
  而且每个工具都多一份 schema。

- 没有任何工具在浏览器里打开页面或截图；搜索和抓取网页则是另一回事。项目的页面在 CI 里用浏览器测试，
  agent 在自己的机器上不需要浏览器。

- 工程师可以从 CI 取回生成的文件。既不能在本地编译，又没法手工把生成的文件写对，条目就会停下来等人。

- 引擎替 agent 运行的命令，只限 agent 自己的命令行做不了的，即要凭据的，比如推送和读 GitHub。agent 在 worktree 里能做的事
  不交给引擎：交给引擎，每次请求要多一轮，还得为引擎替它跑的命令另设一整套约束
  (backend/agent-rounds/permissions.md, "agent 的命令只拒绝两类")。

- 一次测量在对照的代码、它的一个孪生副本和被测的代码上，以轮换配对的方式为一条命令计时，并保留原始耗时：
  机器的噪声随时间漂移，轮换配对能抵消漂移，原始耗时也可以重新分析。
