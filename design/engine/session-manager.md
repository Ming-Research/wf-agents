Decision: Everything about an agent's session (which session a round runs in, what the session holds and is given, what each call cost, the command line it runs in, and keeping a waiting session warm) is one crate, the session manager (`crates/sessions`), which the engine calls before each agent round and between steps: the engine decides when (which cell runs next, when a work waits), the session manager decides and does the rest and records it in `sessions` and `pings`, instead of these pieces spread through the engine, because the owner wants all of an agent's context management in one place that can later move out of the engine's process.

Decision: A line starts a new session at its first round in a work, at the work's first round of a cell a row of the flow leads to with the action `open_session` (the engineer's line at implementing, cell `I1`, and at fixing, cell `T6`; the review of a batch, `B2`; the search, `X2`; the new architect that reads a policy, `P6`), which the chart draws on those rows, and at its next round once the context of its session (the prompt of the last call of its latest round, as recorded) is past the configuration's `agents.context_limit`, 500,000 tokens unless set; the session before ends, the worktree stays, and the new session is given everything its cell's round needs, as any session that holds nothing is; a return sent back is rewritten in the session that wrote it, and the limit takes effect at the round after; each session records why it started, instead of one session per line for the whole work that the command line compacts, because work 9's engineer session reached 312,000 tokens before implementing and 531,000 at its end, every call reading all of it again, while what implementing and fixing need is in the records the new session is given.

Decision: A line also starts a new session at its next round when the owner asks for one with the round's Start or Step, recorded as the owner's; a return sent back is then given whole with why it was sent back, since the new session does not hold it.

Decision: A line also starts a new session at its next round when the model its rounds run on changed (a tier's model changed, or the item moved to another tier), instead of resuming the session on the new model, because a model's prompt cache holds nothing of a session another model ran, so the whole session would be written again at the new model's price, while a new session is given only what its cell needs; no keep-warm ping goes to a session whose next round starts anew this way.

Decision: When a work waits (paused, held by the owner's pause of every work while the owner keeps sessions warm then, for the owner's or the architect's answer, or at a row that waits for other items) and every way from where it stands leads to a round in one line's session, the session manager sends that session one minimal message 55 minutes after its last call, while the command line's prompt cache still holds the session, and again every 55 minutes, at most 39 times in one wait; it sends none when that round will start a new session anyway (a cell its line starts one at, a session past the limit, or one the owner asked for), none while every work is paused and the owner switched keeping warm off, none beside a round of the session, which the engine's single thread makes impossible and the session manager checks, none once the cache has let the session go; a ping that failed is tried again a minute later; a ping holds no slot, instead of letting the cache expire, because a call after the hour writes the whole session again at forty times the price of reading it (work 9 paid $3.28 for two such rewrites), and 39 reads cost what one rewrite does. This works around the cache's one-hour lifetime.

Decision: A ping runs the command line of the session's last round exactly as it ran, resuming the session, with only the message changed, instead of a command line built from the configuration as it is now, because the cache is read only when everything that shapes the prompt (the command line, the model, the system prompt, the tools and the structured-output schema) is the same; a changed reasoning effort keeps it while thinking stays on.

Decision: Each ping is recorded with the cell the work waited at and what it waited on (its pause, the owner, the architect, other items or a tool), and its cost as what the session's cost grew by, which the next round's cost leaves out; the anomalies command lists the pings and the work's cost on the page and in the cost command counts them, instead of a cost hidden in the next round or nowhere, because needing a ping means the work waited over an hour, which is an anomaly to fix where it comes from.

Decision: A round that resumes its session within the cache's hour since the session's last call, a round's or a ping's, and whose first call still reads from the cache less than half of what the session held (the last prompt of its round before, as recorded, so that a round that reads only a small fixed part such as the system prompt counts too) missed the cache; the round's usage record keeps what its first call read and wrote (`first_call`), from the command line's stream, since the result the command line reports at the end gives only the whole run's tokens and its last call's. What the round wrote to the cache is not the measure, because it is also what the session gained since, the last answer of the round before and the round's own message: in a trial two rounds of the policy line after a round of tools read all 32,208 and 69,003 tokens their sessions held and wrote 18,304 and 45,129 new ones, which a measure by what was written reported as misses. The session manager tells a miss with the tokens of the session its first call did not read, what writing them again cost beyond reading them, and the parts of the command line and the variables of its environment that differ from the session's round before, or that none does; the environment a round's record keeps is the variables the engine sets and those the command line reads that it inherits from the engine's own, a secret only by its digest, since the command line inherits the engine's whole environment and a variable there can change its prompt. The engine keeps it in `cache_misses` and tells the owner in a notice that names it a fault of wf-agents, to which a further miss with the same cause on the same line of the same project adds while the notice is unread or a matter forwarded from it waits in an architect's queue, instead of counting misses into the numbers the architect reads or finding them by reading the records, because wf-agents runs other projects too and a miss is its own fault, to be fixed in wf-agents whichever project it came up in, and a new cause, such as a new version of the command line, shows the first time it happens (in a trial the architect's rethinks read 6,492 tokens and wrote 340,000 to 450,000 again).

Decision: The session manager starts a round at the reasoning effort its cell declares in the flow, whatever the model the item's level picks, instead of an effort for each level, because the owner set the effort by the kind of task each cell is, and a level is only a model; changing an effort is a change to the flow. A changed effort between rounds of a session keeps its cache.

Decision: While a round runs, the session manager gives its command line two hooks (`--settings`): after each tool use, `wf-agents deliver` hands in the interjections waiting for the round's line, records them as delivered in the round, and the round's return is checked against them as against those its message gave; after a compaction, the session is given again at once what the round's cell is given as a session that holds nothing is sent it, from a file kept while the round runs; instead of interjections waiting for the next round and a compacted session carrying on without what it was given, because the flow says the session manager does both, and the command line adds a hook's output to the session where the agent is. A round that has ended takes no interjection, so a keep-warm ping, which runs that round's command line again, hands in none; nor does a round of a cell that reads no interjections, as a new architect reading the policy being set, which must see only the text, whose hook is given no line.

Decision: The session manager sets up a work's worktree and branch at the start cell, on a machine with a free slot (the first machine when none is), reports each machine's free slots from the works holding one, says whether a head a round hands in is the worktree's HEAD with nothing uncommitted, and ends a work's sessions at its end, where the worktree is removed and the branch stays, instead of the engine doing these beside its flow steps, because worktrees and sessions are what the session manager keeps for the works, and they are caches the database and the branch on GitHub can make again.

Decision: The session manager brings a project's architect's worktree for a graph (design/harness/agent-cli.md) to the latest main before each round that runs there: it fetches main, detaches the worktree at it and drops whatever was changed there, and makes the worktree when it is not there, where a directory that is no worktree gives way to it; a round it cannot ready this way does not run, and the work waits for the owner with why. The wake's worktree stands where the wake's directory stood, `worktrees/architect/<project>`, so that the wake's line goes on in the session it had, which the command line resumes only in the directory it ran in. This is instead of a worktree made once and left as it was, because the architect judges the project as main stands now, and a worktree that only reads holds nothing worth keeping from one round to the next.

Decision: A round whose session starts afresh records why in its input (`engine.new_session`): no session of its line going on yet, a fixed place of the flow, the context past the limit, another model, or the owner's ask, and the page says it on the round; a new session the flow fixes is drawn as the action `open_session` on the rows into its cell, instead of a mark on the cell, because the owner reads the fixed places on the chart with the other things the engine does on a row, and a new session that is not fixed can only be read where it happened.

Decision: What is said to a line that is not running waits for that line's next round, at the top of its input, and no round runs off the graph to answer it; once a work is at its end (`E1`) nothing more can be said to it, and what it was told and never handed in is marked on the owner's words themselves in the work's group as never received (the action `tell_undelivered` that told the owner by a notice is gone, and an older flow version's `E1` naming it tells nothing); a word that needs no answer, as the owner confirming every decision of a design card, is marked so (`interjections.informs`) and given at the line's next round without taking a work at an engine step to `A4`; instead of a round of an agent off the graph that only answers, because a round the flow does not draw is behaviour out of its sight (Article 7), and a word that changes nothing must not send a waiting work to choose the way on.

Rejected:
- One session per line, compacted by the command line: rejected because a session read again whole at every call grows the cost of each call with the work, and compaction keeps what the command line chooses, not what the cell needs.
- Pinging a session whose cache has expired, or without a cap: rejected because a ping after the hour writes the whole session again for nothing, and an endless wait would cost more in pings than the rewrite it saves.
