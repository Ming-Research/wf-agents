Decision: A thing the flow names, where its name heads what the owner reads (an input, a field, a form, a tool), is its name in words in the step of the heading it is, then its code in `--fontStack-monospace` at `--text-body-size-small` in `--fgColor-muted`, then its type and flags as body small `--fgColor-muted` words joined by a bar, with no border and no background, a mark the owner looks for (the main path) a secondary `Label`; a list of such things that each open (the inputs, the rules and formats, what a session held) is rows `--base-size-2` apart, each a `Details` whose summary is the chevron, its number if it has one, its name, its code and its facts, wrapping under the name, its content indented by the chevron's width. Decision: The settings are a section for the installation and one for each project, each holding first what the owner changes on the page and then, under a sub-heading naming the file ("Changed only in install.toml"), what is changed only in the configuration's files, as label and value pairs, a path, a command or a name of the configuration written as a code; a rule text a project's agents are given is a fold one step down, its title the rule's name, holding the text as a sheet (what is sent to an agent); a project's constitution is named by its path, its text being the project's own; the login accounts the agents may run under are rows, each the account's email, its directory's name as a code after it and the one in use marked by its state's chip (`StateChip`, accent, as what runs), the others signed in a small `Button` Use; one Save, the primary `Button`, writes the rest, instead of a page of the tiers alone, because the owner keeps the whole configuration from one place and must see at a glance what the page can change and what only the file can.

Decision: A setting in a form that one Save writes (the settings) is a Primer `FormControl` holding its label, its control and what is wrong with it as `FormControl.Validation` (ours, after Primer's forms): a `TextInput` for words and numbers, a `Select` for a choice from a fixed list, a `Checkbox` for on or off; a list the owner edits row by row (a project's observation tags) is a table of small `TextInput`s, each row with an invisible small `IconButton` with an `XIcon` that takes it out, and a small `Button` with a `PlusIcon` under it that adds one, instead of a `ToggleSwitch`, which acts at the click, because nothing in the form takes effect before Save, and a list of pairs reads as a table.

Decision: A command the owner runs by hand outside the page (signing a new login account in) is a code block as the markdown draws one (`--bgColor-neutral-muted`, `--borderRadius-medium`, `--fontStack-monospace` at `--text-codeBlock-size`) with an invisible small `IconButton` with a `CopyIcon` beside it that copies it, and what to do with it in small `--fgColor-muted` text over it, instead of a sign-in flow on the page, because the CLI signs in only in its own terminal, and a command copied whole is not mistyped.

Decision: A command whose effect reaches past what it names (switching the agents' login account, after which every line starts a new session) asks first in Primer's `ConfirmationDialog`, its title the question, its body what follows, its confirm button the command's verb, instead of acting at the click, because the owner must know what follows before it happens, and a question the page asks over itself is answered once.
