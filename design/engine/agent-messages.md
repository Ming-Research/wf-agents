Decision: An agent round's message is an instruction and materials: the instruction (the cell's task, the materials to work from by their addresses, and why the round happens) is given every time the cell is entered, even word for word as the last time, while each material (rules, the item, settings, the repository guide, other cells' and engine steps' outputs, tool results, replies, interjections, return formats) is given once in a session and referred to by its address after, because the instruction is what steers the round, while a material repeated to a session that holds it spends its context and hides what is new.

Decision: Whether a session holds a material is decided by the engine as it runs, from the record of what that session was given and handed back since its last compaction, by content: a material identical to one it was given or to a value of its own returns is held, and after a compaction it holds nothing, instead of the compiler working out statically which inputs a session holds, because a static answer has to hold on every way to a cell, so loops and resumed cells were given the same values again, values read through the database were never held even when the session wrote them, and an input taken as held vanished from the prompt with no pointer to it.

Decision: A material comes from one of three places, under one rule: written by the session's own line (its returns: never given, only referred to); needed from the start (rules, the item, project settings, the repository guide, the forms every return shares, the query tool's description with the database's index among them: given the first time the session needs them); or from outside (other lines' and engine steps' outputs, tool results, replies, interjections: given when a new version appears that the cell needs); a material with nothing in it is not written at all, because a session needs each thing once, at the time it first needs it.

Decision: A value a round produced is addressed by the round, the cell and the field path as the flow writes it, joined by middle dots, such as round 39, cell 4, end.test_changes[added], its version being the round; every message starts with its own round's address, so an agent's own return sits in its context under that heading; the other materials are rule:, config:, item:, card:, ij: (an interjection) with a name or id, format:common and format: with a cell, and what the engine computes carries the round it computed it for; identical content is one material, addressed by the earliest round that produced it, and the instruction names a concrete address, never the latest of anything, instead of inputs named by descriptions written for people, because an address points to one version the agent can find in its context.

Decision: The work's history is given to no cell; a cell called in from another line is given the outputs of the engineer's line it needs as named inputs, and an engine step's output reaches agents only as a material of the cells the flow says read it, instead of the history, because the history re-sent every round's whole record each round, descriptions written for people included, and carried engine steps' inputs, which never belong in an agent's context.

Decision: The locked acceptance is addressed by the round that locked it (the design's acceptance, or the advisor's new acceptance), so a cell that reads it through the database and the design round that wrote it share one material; the gate that locks it reads the design's acceptance it is about to lock, because the locked text is that round's own value, and two addresses for one content would give it twice.

Decision: The index of the database (each table and view with the first line of what it holds) and the query that reads one in full are in the query tool's description, which the compiler writes from `db/schema.sql`, so they come with the return formats once in a session, instead of a material of their own or the whole schema with its comments, because an agent reads them where it learns to ask for the tool, a round reads a few tables, and a definition with its comments is one query away.

Decision: The forms every agent's return shares (asking, tools, pausing, answers, redirect, side reports, progress) are one material holding every tool and role any cell has, and each cell's own answer is another, which also says which shared forms the cell has; both are given once in a session for each flow version and the instruction names the format to hand in, while the command line keeps its one structured-output envelope and the engine checks each return against the cell's whole schema, instead of each cell's whole return schema in every round, because the shared forms are most of every schema and do not change within a flow version.

Rejected:
- Working out at compile time which inputs a session already holds: rejected because a static answer must hold on every way to a cell, so it is too conservative for loops and resumed cells, cannot see what was read through the database, and drops a held input from the prompt without saying where it is, while the record of each session says exactly what it was given.
- Giving the work's history to the cells called in from other lines: rejected because it repeats every round's whole record in every round instead of the outputs a cell needs, and puts engine steps' inputs in an agent's context.
- One address for each source an input reads, such as the database view the acceptance is read through: rejected because one content then has several addresses, and a session that wrote a value is given it again under another name.
