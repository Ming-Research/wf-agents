### decision a-run-that-changes-the-code-takes-main-in
A work is not held to the main it started from: before the first round of each run of a cell that says it changes the code, the engine merges into the work's branch main's head as the host last gave it, and the round is told the files main changed since the branch last took it in. A round later in the run takes nothing in.
Why: A work held to one main from its start to its merge meets what others merged meanwhile only at the check before its merge, where a conflict costs the most; taken in as each such run starts, it is met while the work is being done, and an agent whose session goes on knows which files to read again rather than working from what it remembers. Taking it in at every round lost because a merge in the middle of a run changes the code under an agent that is still working on it; leaving it to the agent lost because it is exact work an agent sometimes gets wrong (principle mechanical-engine). Main is an input only of the check before the merge: every cell reading main was turned down because it would run a whole work again at each merge of another.

### decision a-conflict-is-the-agents-to-merge
Where main's head does not merge into the branch without a conflict, or the worktree holds changes not committed or a merge under way, the engine takes nothing in, leaves the branch and the worktree as they were, and tells the round why, with the files in conflict or the changes, for its agent to merge main itself.
Why: Resolving a conflict is judgment, which belongs to the agent that knows the change (principle mechanical-engine), and a merge over changes not committed can lose work that was paid for (principle keep-what-was-paid-for). A merge begun and then taken back on a conflict lost to finding the conflict without changing anything, which leaves nothing to undo if the engine stops between the two.

### decision what-came-of-taking-main-in-is-kept-for-the-run
What came of taking main in is kept once for the run, beside its rounds, and every round of the run given its task is told that, not taken in again; it is no block of the work. The run's merge is made with words that name the run, by which a head that is that merge is known again as what the run took in where the engine stopped before keeping it, and by which the check before the merge does not take it for a merge of its own.
Why: A round given again after the engine stopped, or tried again with its session begun the other way, must be told the same as before, and taking main in a second time would find it held and tell nothing (principle effects-known-as-done). Known by the engine's identity alone, the run's merge would be taken by the check for its own, which would then write that it had merged main for the check. As a block written while the run is at rest, it would make that run stale if the cell read it, and be read by no one if it did not (principle every-field-has-a-reader).
