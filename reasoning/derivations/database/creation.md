Decision explicit-init: A database is made only by the explicit command `wf-agents init`, which runs only on a data directory that already passes the data-directory check (a git repository with a commit and a valid committed configuration) and refuses a place that already holds a database; every other command, the engine included, opens an existing database, for reading only or for writing, and fails with an error that names the database path when there is none, because the files cannot tell a first use from a mistaken path (observed: the owner's data repository keeps the database directory out of git by its own ignore rules, which this repository does not enforce, so a fresh clone of it has no database; where the database were committed, a fresh clone would carry one and this ground would not hold), so only a deliberate act separates the two, and then a missing database is always an error and creation never happens by accident.

Rests on: C:design-on-merit, F:data-repo-ignores-database, D:data-directory, D:config-committed

Rejected:
- Only the engine creates it: rejected because a pass of the engine would be needed before the first item can be added, a command meant for taking works would double as initialisation, and the engine itself would still create a stray database silently in a valid data directory that has none.
- Creation stays with the commands that already check the configuration (adding an item, starting the engine): rejected because those commands would still create silently in a valid data directory that has no database, such as a second clone, so an item could be written into a database the engine never reads; it shrinks the places that create but keeps creation implicit, where the chosen way makes every creation a deliberate act.
- A creation option on those commands: rejected because it is the same explicit act in an irregular shape: an option meaningful on only some commands, which ties creation to commands that do other work and tends to be copied into scripts and aliases until it protects nothing.
- A marker in the data repository (create implicitly only where a tracked database directory exists): rejected because it tells a mistyped path from a real clone but not a valid clone from the intended one, so an item can still be written into a database the engine never reads, and the rule would live in files of the owner's data repository that this repository can neither check nor change.
- Check only that the path is a data directory and leave creation as it is: rejected because it does not touch a data directory that has no database, it makes read-only views fail when the configuration is broken, and it keeps opening an existing database and making a new one in a single operation, so a caller that forgets a check still creates.
- A check that the database is there before each command opens it, with the open still able to create: rejected because the protection rests on every caller remembering the check, a caller that opens directly (the page's write path, a later command) creates silently, the database can be removed or replaced between the check and the open, and the check's rule for an existing database and the creation's rule for an empty place are written twice and can drift, where the chosen way makes opening unable to create.
- A flag on the call that opens the database saying whether to create it: rejected because creation then stays one boolean away from every caller and test helper, and opening, creating and migrating remain one operation, where the chosen way gives creation a call of its own that only `init` makes.
- Asking on a terminal whether to create when the database is missing: rejected because every command then behaves in two ways, with and without a terminal, a mistyped path costs one reflex answer to make a stray database, and the engine, which has no terminal to ask on, still needs a command that makes the database.
- Commands as requests to a running engine, which alone opens the database: rejected because no command could be used while the engine is stopped, as adding an item can be now, and someone must still make the first database, so the first use only moves to the engine's start.
