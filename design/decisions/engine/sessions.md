# Sessions

When a line of a work goes on in its session of the agents' program and when it begins a new one.

### decision a-new-session-loads-again-through-its-line-s-datum
Because a new session holds nothing of what the line's loading cell read, a new session of a line writes the line's own datum, `<line>_session`, which only a cell that must load again watches; the engineer's line has one, the deep research none.
Not knowing this, an agent would give every line the datum, or one datum for all, and every other line's loading cell, a deep research round at its highest effort among them, would run again for nothing at each new session or compaction.

### decision a-lost-session-keeps-its-id
Because the round that finds its session lost has begun before the new session is recorded, a session the agents' program no longer has is begun again under the same id, and a compacted one goes on under it; only a new session for another reason takes an id of its own.
Not knowing this, an agent would give the lost session a new id, and the rounds after would count a different session than the one that round began.

### decision no-new-session-when-the-cache-expired
Because going on writes the session to the prompt cache once, where a new session reads again what its rounds had read, which costs no less (judgment, not measured), a line does not begin a new session for a cache that expired while it waited.
Not knowing this, an agent would begin one on a long wait, to save the cost of writing the cache again, and pay for the loading cell's reading as well.

### decision waiting-sessions-are-kept-warm
Because a write of the cache kept an hour costs forty reads on Opus and Sonnet 5.5, a waiting work's sessions it can come back to are sent keep-warm pings, whoever holds the work: the engine as it opened, the owner's pause, or a question to the owner; only the wait every work shares and the engine's pause for spending too much stop them.
Not knowing this, an agent would stop the pings with each hold, and no ping would ever run: a work waiting eight hours at a cell had its session let go cold (principle keep-what-was-paid-for).

### decision keeping-warm-is-the-engines-state-not-a-setting
Because the owner switches it on the page and a switch must act at once, whether waiting sessions are kept warm is the engine's own state, kept with the installation as the pause of everything is, and no setting; it is on until the owner switches it off.
Not knowing this, an agent would make it a setting read as the engine starts, so that a switch over it would do nothing until the engine started again, and the thing would stand in two places (principle one-thing-one-place).

### decision no-round-begins-beside-a-ping
Because a round begun beside a ping is filled from the session as it stood before the ping, which may compact it, and its cost counted without the ping's, nothing else of a work runs while its pings are under way: its next round and the letting go of its worktree wait for them.
Not knowing this, an agent would let a round or the letting go of the worktree run beside a ping, taking the directory the ping's program runs in, and the round's cost would be wrong.

### decision a-session-is-compacted-at-the-installations-number
Because a session replaced for its size holds nothing of what its cells read and did, every round's command line gives the agents' program `sessions.compact_at`, the installation's own number, at which it compacts the session; the engine begins no new session for size, and `--autocompact` in `agents.args` is refused.
Not knowing this, an agent would replace a session at some size, as was once done at 808,765 tokens, and the line's cell would go on knowing nothing of what it had built; it would also set the number in a second place (principle one-thing-one-place).

### decision the-compact-number-is-not-lowered-by-a-line-s-history
Because a session larger than its line's earlier ones is no fault, no number drawn from the history of a line's rounds lowers `sessions.compact_at`; a prompt too long for the model is the only size that begins a new session.
Not knowing this, an agent would apply principle judged-by-own-history to the size, as was tried: the line's sessions were 81,768 tokens, so the session was replaced at 103,764 under an installation number of 500,000, though it held what the line needed.

### decision the-projects-files-as-the-work-has-them
Because a change of the project's guide, constitution and tree rules made on a work's branch is meant to hold in that work, a session's system prompt reads them from the work's worktree, never from main; what keeps a work from changing its own rules is that the files are protected (principle protected-files-are-the-owners), not where they are read.
Not knowing this, an agent would read them from main, and a change the owner made on the branch would not reach the work.

### decision the-system-prompt-is-kept-with-the-session
Because the worktree changes within a session, by the work's commits and by main taken in, a session's system prompt is kept in the data directory as it began, and every round of the session is given the kept one, however it begins in it (principle the-system-prompt-holds-what-a-line-shares).
Not knowing this, an agent would make the prompt anew for each round, and the session's prompt would change from round to round and break its cache.

### decision the-form-is-kept-as-the-system-prompt-is
Because the form of return is the system prompt sent another way and a session is given one form (principle one-form-of-return-for-a-session), it is made as the session begins, from the flow installed then, and kept beside the system prompt by the same means.
Not knowing this, an agent would keep it by a means of its own, and the two ways of keeping what a session began with would drift apart (principle one-thing-one-place); made anew for each round, it changed within a session as another flow was installed.

### decision lines-say-where-sessions-begin
Because the lines already say which cells share a session, no cell begins a new session of its line at a place of its own; a cell that must not go on in another's session is on a line of its own.
Not knowing this, an agent would give a cell a mark that begins a new session part-way through a line, a second way of saying what lines say, and the chart would need a mark for it.

### decision a-compaction-reopens-the-session-under-its-id
Because a compacted session holds a summary where it held what the line read, a compaction by the agents' program during a round is recorded as the session reopened, once for each compaction, and the session goes on under its id (decision a-lost-session-keeps-its-id).
Not knowing this, an agent would record no reopening, so that a loading cell watching the line's datum would not run again, or would give the session a new id, and the next round would begin a session that exists.

### decision a-fork-keeps-the-sessions-tools
Because the tools stand at the front of every request, the cache is read only as far as a request begins as the session's did, so a fork of a round's session is given the session's last command line whole, its tools among it, and a hook refuses each tool but the program's own for the return.
Not knowing this, an agent would take the tools from the fork to keep it from using them, and the fork would read none of its session from the cache and pay for all of it again; a hook refusing the return's tool too would leave it no way to answer.

### decision a-fork-begins-at-the-end-of-its-round
Because a fork asked of a round must hold only what that round saw, where the session went on past it the fork begins at the round's last message, as the stream of its latest try naming one says, and is refused where the session was compacted or begun again after that round.
Not knowing this, an agent would begin the fork at the session's end, and a fork of a plan would hold the later reviews, the owner's answers and the whole build, and could not show how the plan was written.

### decision a-forks-cost-is-counted-from-its-base
Because the first call after the round read what the round left from the cache and wrote it on past it, no later call read that again (judgment, not measured), the fork's cache is counted from that call within the cache's life, else from the round's end, and its spend is the program's total less all the session cost before.
Not knowing this, an agent would take from the total only the cost up to the round: the total counts the whole session, and a fork of a plan was told as $12.28 where it cost about $0.65.

### decision a-fork-of-an-ended-work-stands-in-for-its-worktree
Because the agents' program finds a session by the directory it ran in, and an ended work's worktree is let go while its branch is kept (decision letting-go-at-the-end), a fork of its session is run in a checkout of the kept branch on no branch, made at the worktree's place and taken away after.
Not knowing this, an agent would leave the checkout or use an empty directory: the next fork would take it for the worktree, a reopened work could not start on it, and the program would not see a repository as the rounds did.

### decision a-forks-spend-is-kept-with-its-answer
Because a fork is a look of whoever plans the work at one round's words, asked apart from the work's own way through the flow, its spend is said to whoever asked and kept with its stream and answer beside its round's.
Not knowing this, an agent would put the fork's spend into the work's records, and a look would be counted as the work's own cost.
