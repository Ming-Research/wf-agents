# A changed flow walks the records

How a change to a flow reaches the works under way. The walk already goes over a work's records on a changed graph,
and a line whose session began with another system prompt or form begins a new one (5); a cell's specification as a
datum it watches, the walk without acting, and the table of earlier ids are not built.

1. A changed flow is installed by walking each work's records on the new graph: a cell that did not change is passed,
   a new cell has no record and runs when the walk reaches it, and what a cell taken out wrote stays in the item.

2. The specification of a cell is a datum that cell watches. A change of it is a write from outside, and whether it
   matters to the works under way, so that they run the cell again, the owner says when approving the change.

3. Walking without acting, before the change is approved, shows for each work from which cell it would run again.

4. A record is found by its cell through the table of earlier ids (principle cell-numbering).

5. A line's session keeps the system prompt and the form of return it began with. So a changed system prompt or form
   reaches a work under way as a new session of each line whose kept ones differ from what a new session would begin
   with now: the line begins it at its next round, as for a change of model, and what was handed in still counts
   (decision a-changed-system-prompt-or-form-begins-a-new-session).

Records are kept by cell and by the versions each run started from, not by a step in a course taken, so they still fit
a graph that has changed; and a changed cell is one more datum it watches that changed (principle
flow-change-spares-works).
