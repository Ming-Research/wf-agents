# The observations

What agents come across outside their works, kept for the owner as the installation's observations.

### decision an-observation-is-a-plain-text
An observation is a plain text that an agent reported with its work, cell and round or an architect added with the project that reported it; the installation keeps it and gives it to no cell.
- rejected: an agent proposed that each observation say whether it does harm now; the owner rejected it, because only a defect can do harm.
- rejected: an agent proposed that each observation say what follows if it is left alone; the owner rejected it, because that was strange as well, and the architect judges how urgent each one is.
- rejected: an agent proposed giving a work's first cell the observations its item took in; the owner rejected it, because observations are the architect's, written, kept, deleted and merged by it, as items are.

### decision observation-tags-are-free-names
An observation carries tags that are free names, checked as an item's tags are, and one list of the names in use counts them for items and observations alike.
- rejected: an agent proposed that tags come from a fixed set named in the settings, and any other be refused; the owner rejected it, because it needs no new setting or mechanism, and a misspelled tag only adds a name, which the architect avoids by looking at the names in use.
