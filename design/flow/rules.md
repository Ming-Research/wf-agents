Decision: The rules agents follow are the flow's rules, written in `flow/flow.json` and independent of any project, each given to cells as a conditional input: the general rules to every agent's cell, the engineering standards to every engineer's cell and the advisor's, and the design tree writing, the review table and the design tree review to the cells that name them; a rule given to every cell of some lines names those lines, and a cell does not name it again, instead of rule files in the project's configuration, because how an engineer, a reviewer or an adversarial tester works is the same in every project and belongs to the flow those roles are cells of.

Decision: The architect is given a rule of its own, on its line, after the general rules every graph shares: how it judges (by each project's constitution and the policy in force, the policy deciding between projects), what is its to decide and what the owner's, that it does not do the engineers' work and has what needs fixing fixed rather than fixing it, how it looks at works where they meet the whole and at design cards without ruling on them, when it pauses a work or holds new works and that it says why, what it never does, and how it writes its changes, its notebook and its record, instead of the architect working from its cells' questions alone, because the questions say what to answer at each step, while how the architect acts across them, and where its part ends and the owner's or an engineer's begins, holds at every step.

Decision: The advisor is an engineer that runs on a higher-level model, and is given what an engineer is given, the engineering standards included, instead of rules of its own, because the advisor does an engineer's work one level up.

Decision: How a field is written is said in the field's description, where the agent writing it reads it (the problem and its example in the understanding, the comparison in the approaches, the design and its cost in the design, the acceptance in the acceptance, the progress with two examples, what changed in the PR description), and how every field the owner reads is written, with how code examples are written, once in the forms every return shares, which those fields point to, together with the fact that only the return is read, instead of a rule of item writing given to engineers, because a separate rule repeats what the fields ask, and every piece of it is needed exactly where a field is written.

Decision: A field in the owner's language is written in it directly, never as a translation, said in the forms every return shares beside how a field the owner reads is written, as the earlier board's rules said, instead of a text thought in English and put into the owner's language, because the owner reads such a field, and a translation reads as one.

Decision: The engineering standards' lines on the repository say that a repository keeps no TODO file: open work is an item, which code and documents cite by its number, and a public repository by its number alone, as the earlier board's rules said, instead of a list of open work kept in the repository, because the item is where open work is ranked, started and done, and a list beside it goes stale; and the rest of an item is written for the owner, not for a public repository.

Decision: How the architect writes an item is said in its rule of item writing (`item_writing`), given to its line and to the review of its batch: how the title, the problem, why and the acceptance are each written, how an item that takes in more is, and how large an item is; the fields of the change that makes an item say what each part is and the title's limit, and the change's description says the owner reads the item's parts, its title written in English and the rest in the owner's language as every field the owner reads is, instead of each part's rule in its field's description alone, as for the engineer's fields, because the review of a batch (`B2`), which checks that each change is written as items are, is given the rule and not the fields; and the owner reads the item, as the items of the earlier board were written for the owner, while the engineer's own problem, shown over the item's, is in the owner's language already, and titles keep one language for now, which also keeps a title usable where the project must be English, as in a pull request or a branch.

Decision: A review is given its checklist as the review table and the design tree review, and its own way of working in its tasks and its findings: it reviews only the change, reruns no test already green, adds no new style demand, reviews only the PR's own change where it merges main, marks each item passed, findings, cannot be verified or not applicable with no pass without evidence, and gives each finding where it is, the quoted text or the missing evidence, and the reason, quoting both sides of a contradiction; a defect in the PR description is a finding too, instead of the engineering standards as what a reviewer checks, because the standards say how agents work themselves, not what a review checks.

Decision: A project's own rule texts, which its configuration lists, are given to every agent's cell beside the flow's rules, and hold only what is particular to that project, instead of carrying the flow's rules too, because a rule a project needs (such as a goal its projects share) cannot be written into the flow, while the flow's rules hold in every project.

Decision: An input that only says to read something yourself is not an input: what an agent reads to do its task is its own to find, and what a cell must not read, or must read first, is said in its task, instead of an input with nothing in it but that, because such an input told the agent what every agent does anyway.

Decision: The project's design goal is given to every agent's cell, as a conditional input, instead of to the cells that compare approaches only, because every judgment a cell makes is made toward it.

Rejected:
- Rule files in each project's configuration for how agents work: rejected because the same rules then have to be kept in every project, and the flow cannot be checked against them.
- One rule of item writing given to every engineer's cell: rejected because it repeats the descriptions of the fields it governs and gives every cell the parts only other cells write.
- Giving a reviewer the engineering standards as a checklist: rejected because they say how an agent works, while what a review checks is the review table and the design tree review.
