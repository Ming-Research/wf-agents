# The versions of the flows

Which version of its flow a work runs on, what is kept of a version, and how what a work recorded on an earlier one is read.

### decision a-version-is-kept-as-its-files-and-its-outline
A version is kept once as its files, each file once, and an outline made as the engine starts on it, whose parts are only added and may be missing; no version is compiled again.
- rejected: an agent proposed keeping only the files and compiling every version a work ended on again at each start; the owner rejected it, because each later change of the flow's format or the compiler's checks would have to keep the old versions compiling, and old readings would pile up.
- rejected: an agent proposed keeping the compiled flow, or the page's whole view of a work; the owner rejected it, because each changes with the code, and every copy kept in the store would be migrated at each change.

### decision a-move-is-read-through-the-renumberings
A move records only the version, and a work's records, kept under the names they were recorded with, are read through the renumberings between the two outlines of each move in turn.
- rejected: an agent proposed storing in each move what it renames; the owner rejected it, because that follows from the two versions' outlines, and stored it would be a second copy of them.
- rejected: an agent proposed writing the new names over the records; the owner rejected it, because the store's tables are only added to (decision tables-only-added-to).

### decision a-work-that-ended-stays-on-its-version
A work that ended stays on its version and is decided, let go of and drawn by it; at each start every other work is put on the version installed, and a reopened work as it reopens.
- replaced: Reading every work by the flow installed was on main; the owner changed it, because a work that ended was then read by a flow it never ran on, and a cell added after its last would make a merged work go on (principle the-past-as-it-ran).

### decision a-round-is-judged-as-the-cell-it-is-now
A round of a work on a version not installed is judged in the history of the cell it is on the version installed, and only in the flow's history where that cell has no id there.
- replaced: Judging a round of a work that ended by the id its run recorded, read on the flow installed, was on main; the owner changed it, because a renumbered id then named another cell, while a cell's history is its rounds under the id it has now (principle judged-by-own-history).

### decision a-table-that-misreads-a-kept-version-is-refused
The engine does not start while the installed table of earlier ids does not begin with that of a version a work is on, reads two of its cells as one, or one as a cell it neither has nor took out.
- rejected: an agent proposed holding such works at fault and starting all the same; the owner rejected it, because the fault is the flow's, and is mended there.

### decision a-work-kept-before-the-versions-is-on-none
A work kept before versions were is on no version where it had ended as the flow installed at the first start read it: no flow decides it, and it counts only in the flow's history.
- rejected: an agent proposed putting such a work on the version installed at the first start, with a note that it may differ from what it ran on; the owner rejected it, because cells whose ids were given again would still be named as others, and runs at a cell since taken out drawn in no column.
- rejected: an agent proposed rebuilding each such work's version from the repository's history, with the compiler reading the old formats again; the owner rejected it, because the versions would be guesses, the compiler would keep old readings for good, and finding them needs one flow's cell names.

### decision a-work-keeps-what-its-time-went-to
As a work ends, the engine keeps what its time went to as its version reads it, and an ended work's bar is drawn from that; one that kept none shows its waits as not known.
- rejected: an agent proposed drawing the bar of a work that ended from its records alone, a pause as a pause and every other wait as not known; the owner rejected it, because no ended work would show what waited on the owner or on items, and reading those again would need a second definition.
- replaced: Reading what a work's time went to anew from its whole flow at each look was on main; the owner changed it, because a version no longer installed is compiled no more, so what its time went to could not be read again.

### decision a-live-bar-asks-at-its-cells-middles
The bar of a work going on asks what the work waited for only at the middle of each cell less than half of which ran, by the one decision its kept stretches are made by.
- rejected: an agent proposed drawing it at each request from the work's exact stretches; the owner rejected it, because each wait is then decided over the records before it, and at 200 waits it took ten times main's time (data: `research/flow-versions/bar-cost.md`).
