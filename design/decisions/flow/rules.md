# The rules every agent is given

The general and the engineering rules that the flow gives every agent, along with its cell's task.

### decision the-old-rules-came-back
Every agent is given the old system's general and engineering rules, with their meaning kept, changed only where the new design forces it, and written in plain English.
- replaced: The rebuild's own words for agents, written without any of the old rules, was on main; the owner changed it, because the old rules held much of value, settled over a long time, including the basic rules for code.
- replaced: The old rules in their old wording was on main; the owner changed it, because everything in the project is written in plain English.
- replaced: An old rule about the forms of a language, which counted how often a form appears in a project's own tests, was on main; the owner changed it, because it holds only for projects that build languages, and the rules go to every project's agents.
- rejected: an agent proposed deleting that rule; the owner rejected it, because the old rules keep their meaning, and the rule worded for every project holds for each of them.

### decision the-rules-name-no-block-to-ask-in
Where the rules send an agent to the owner or to something it must wait for, they name no block: the agent asks the owner, or says it cannot ask, and tells the engine in its return what it waits for.
- replaced: Rules telling an agent to ask the owner in `questions` was on main; the owner changed it, because the cells of the review lines cannot ask, and the rules describe how agents work, not the flow.
- replaced: The rule that what must be waited for goes in the return as a tool or a question was on main; the owner changed it, because the review lines cannot ask, and each cell learns from its own words how to ask for what it waits for.

### decision a-comment-says-only-what-bears-on-the-code
A comment that an agent writes in code says only what matters to the code beside it, never its status in a process; a comment that does is reported in `observations`.
- rejected: an agent proposed a rule saying at length what a comment holds and leaves out; the owner rejected it, because it was too long.
- rejected: an agent proposed that a comment never say the code's history; the owner rejected it, because history may be written.

### decision nothing-is-kept-in-the-command-lines-memory
The rules tell an agent to keep nothing in the command line's own memory, and say nothing about where to put what must last.
- replaced: The rule's second half, that what must last goes into the round's return, was on main; the owner changed it, because a fork showed R0 taking what it read as something that must last and putting it into a block made for something else.

### decision the-agents-choose-the-language-they-pass
Agents choose the language of the texts they pass to each other; only the title, which is written into the repository, and the plan for the owner have a set language.
- replaced: Blocks telling the agent to write in English was on main; the owner changed it, because the language of what agents pass to each other is theirs to choose.
