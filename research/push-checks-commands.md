# Commands for the checks `ci` runs before it pushes

Item #296. This note holds the commands a project could list as `[[ci.push_checks]]` for wf-agents, how each finds its
program, and the numbers the choice rests on, taken on 2026-11-04 (the engine's records read at about 23:30 UTC). It
serves the report of item #284, which classifies each command by how it finds its program and reads them from here,
and the review of #296. It is deleted once #284's report has read it and the configuration holds the commands.

Each claim says how it is known: (measured) on the data or a run of the date above, (read) from the source, (inferred)
not tried.

## 1. The commands

The engine runs a check without a shell, in the root of the work's worktree, with the engine's environment. The head
is the worktree (the tool refuses a head that is not the clean worktree's HEAD), so what the head holds selects the
programs below: a file of the repository can change which toolchain or script runs.

| Check | Exact command | How it finds its program (read) | Listed for wf-agents |
|---|---|---|---|
| format | `cargo fmt --all --check` | `cargo` through PATH, a rustup proxy; the proxy picks the toolchain from `RUSTUP_TOOLCHAIN` if set, else from the nearest `rust-toolchain.toml` upward from the worktree root, which is a file of the head; `cargo-fmt` and `rustfmt` come from that toolchain. The very command of the CI's lint, first step (`.github/actions/lint/action.yml`). | yes |
| types of the page | `client/node_modules/.bin/tsc --noEmit -p client` | A path in the worktree: `client/node_modules` exists only after the tool `dependency_sources` ran `npm ci` for `client/package-lock.json`, and then holds the packages the head's lock file locks. Through the package script (`npm --prefix client run typecheck`) the program would be whatever the head's `client/package.json` says. | no |
| English | `cargo test -p wf-agents --test english` | As the format check for `cargo`. The package `wf-agents` depends on `web`, whose `build.rs` embeds `client/dist`, so the test needs `npm run build` first and compiles the workspace, and the build runs the head's `build.rs` and macros. | no |
| types generated by Rust | `sh -c 'WF_AGENTS_GENERATE=1 cargo test -p api --locked --test typescript && git diff --exit-code -- client/src/api.ts'` | As the format check for `cargo`; it compiles the workspace crates the `api` crate depends on. Two steps and an environment variable, so it needs `sh -c`. | no |

## 2. Why only the format check is listed (measured, queries in section 4)

| Check | Pushed `ci` calls where the log shows it red since 2026-11-04 16:54 UTC (75 calls) | All 798 recorded calls | Runs in seconds? |
|---|---|---|---|
| format | 10 (13%) | 83 | yes: `rustfmt --check` on 171 files took 2.3 s (research/format-before-ci.md) |
| types of the page (`tsc`) | 1 | 5 | no `client/node_modules` in a fresh worktree; the run itself unmeasured |
| English | 5 (log mentions the test's name; includes runs where it passed, so an upper bound) | 19 (same) | no: needs the page built and the workspace compiled (read) |
| types generated by Rust | 1 | 2 | no: compiles |

The ten format reds waited 244, 183, 241, 202, 181, 182, 221, 141, 221 and 241 s (mean 206 s). A check is worth its time
(Article 3) when its chance of finding something times the wait it saves exceeds its own run: 0.13 * 206 s is about 27 s
against about 2 s for the format check; the others lack a run that takes seconds.

## 4. Queries

On the engine's database with its `query` tool. Regimes of the fast CI, by the `run` field of the result and by whether
the request names the lint:

```sql
SELECT json_extract(result,'$.push.run') AS run, (args LIKE '%lint%') AS lint_named, count(*) AS calls,
  min(id) AS first_id, max(id) AS last_id,
  sum(result LIKE '%Run cargo fmt --all --check%') AS fmt,
  sum(result LIKE '%in_english%' OR result LIKE '%is in English%') AS english,
  sum(result LIKE '%Run npm run typecheck%') AS tsc,
  sum(result LIKE '%git diff --exit-code -- client/src/api.ts%') AS types
FROM tool_runs
WHERE tool = 'ci' AND json_valid(result) AND json_extract(result,'$.push.verdict') = 'pushed'
GROUP BY 1, 2 ORDER BY first_id;
```

The runs of 2026-11-04 16:54 UTC on are those with `run` among `named_and_checks`, `named`, `checks` and `none`. The
counts over every recorded call:

```sql
SELECT count(*) AS calls, sum(result LIKE '%Run cargo fmt --all --check%') AS fmt,
  sum(result LIKE '%in_english%' OR result LIKE '%is in English%') AS english,
  sum(result LIKE '%Run npm run typecheck%') AS tsc,
  sum(result LIKE '%git diff --exit-code -- client/src/api.ts%') AS types
FROM tool_runs WHERE tool = 'ci' AND result IS NOT NULL;
```
