Decision: Work is half done only when the engine stopped in the middle of it, when the engine is updated, or when an item comes from outside this flow, and each is handled by what it is, instead of an item carrying a mark of something to take over, because nothing else leaves work half done, and a mark would presuppose how it arose.

Decision: When the engine crashed or was stopped and starts again, or is updated without a change to the flow, the same work goes on, on the same flow version, at the same cell, in the same session: the round that was running is recorded as cut off, and the next round's message says only that it was cut off midway and that the agent first looks at the worktree as it is now (the files changed, the commits made) before going on, instead of the whole message again, because the session holds everything the cut-off round was given, and only what happened in the worktree since is unknown.

Decision: When the flow moves to a new version, a work on an older one is taken over when it next goes on (the owner continues it, steps it, or starts all works), not when the engine starts: it stops, saying why (the round it was in is cut off, its design cards are replaced and its asks of the owner that are still unanswered need no answer), and its item gets a new work on the new version from cell `S1`; the old work ends at cell `C1`, from the cell it stood at, which it keeps as where it stopped, with new sessions, before any item from the queue; until then the owner still rules on its design cards and answers its asks on the page, and the new work is given those rulings and answers as it is given everything earlier works left, and the page says on such a work that it is on an older flow version and is taken over when it goes on. Instead of old works running on to their end, because a work on a flow that is no longer the flow does what the flow no longer says; and instead of every work on an older version taken over as soon as the engine starts, because the owner's works then waited on rulings and answers the owner was about to give, which a takeover at once would have thrown away. A step takes the work over and runs the new work's first round, and the new work stays paused, in the owner's hands, when the owner had paused the old one. A new work that takes over takes a slot only when one is free, as every work does: those that find a free slot start at once, in the order of the works they replace, and the items of the rest wait at the head of the queue, ahead of the items queued before, in the same order, and start as slots free, instead of starting every one at once, because a machine's slots say how many works it holds, and a change of flow does not give it more.

Decision: Cell `S1` takes over what exists: an item worked on here before takes over its latest earlier work's branch, its worktree (reused when it is still there, made afresh from the branch otherwise) and its pull request; an item imported with a branch takes that branch and the pull request imported with it; any other item gets a new branch from main. Cell `R1` is given, as pointers only, what already exists for the item (its earlier works with how far each got, why it ended and the queries that read their rounds, returns, design cards and asks; where an imported item came from; the branch, with the git commands that show what it adds beyond main; the pull request, with the gh commands for its description, comments, reviews and checks), and is told to see first how far the work got, then research as usual, keeping what still holds and saying why for what does not; every cell after runs as usual, instead of the engine judging mechanically which cells a work may pass, because what still holds after a change of flow, or after work done by another agent outside this flow, takes judgment, which belongs to the agent.

Decision: An item imported from outside this flow holds the facts the import records: where it came from, its branch and that branch's pull request; nothing else is assumed of an item, and how items are imported is decided apart.

Decision: An item leaves the dispatch queue when a work starts on it, and an item may be queued again once its works ended: an item is ready when it is not cancelled or held, has no work running, waits for no unmerged item it depends on by a blocking dependency, and is queued or not done, instead of only items never worked on, because an item must be able to have a new work, and the queue holds what waits to start.

Decision: The flow names how a work ends as actions of the cells it ends at: `E1`'s (queue a report's what to do next, withdraw what the work raised, end its sessions, remove its worktree) and those of `C1`, the end of a work cancelled or taken over, which no row leads to (withdraw what it raised, replace its design cards, close its asks of the owner, end its sessions, remove its worktree, close a pull request that never merged), each one part of the one place a work's end is written (`ending::end`), instead of a shared ending only the engine's code says, because what a work's end lets go of is behaviour the owner reads on the chart (Article 7).

Rejected:
- A mark on the item of something to take over, set by whatever stopped the work: rejected because the work that exists (an earlier work, a branch, a pull request) says what there is, and a mark could disagree with it.
- Letting works on an older flow version run to their end: rejected because they follow a flow that is no longer the flow.
- Taking over every work on an older flow version as the engine starts: rejected because it ended works whose design cards and asks the owner was still to rule on and answer.
- Passing cells mechanically when an earlier work had passed them: rejected because whether what was done still holds under a changed flow, or after another agent's work, cannot be told mechanically.
