# Failed rounds

### decision a-shared-cause-is-one-wait
A round that fails at the account's usage limit, for a command line that cannot run, or for want of the network holds the rounds of every work, as one wait worked out from the records of every work; no work is paused for it, and every work goes on by itself once the wait is over.
Why: One cause stops every work alike: paused one by one, each would wait for the owner to start it by hand once the cause had passed, and a mark written on each would have to be lifted on each.

### decision the-wait-holds-what-its-cause-stops
At the usage limit and for a command line that cannot run the wait holds only the agents' rounds; without the network it holds the engine's own acts as well. An act that meets the network gone before any agent's round has fails as a cause no kind tells apart, and pauses its work.
Why: The engine's acts need no agent but may reach the network (a push, a pull request, a merge on a host), and failing there one by one they would each wait for the owner; held at the usage limit they would wait for nothing.

The backup of the records is held by neither this wait nor the owner's pause: see decision backup-is-the-engines-own-tick in backup.md.

### decision no-round-tries-the-network
While the network cannot be reached, the engine looks at it itself, which costs no round, and a round tries only once a look reaches it, or now and then in case what is looked at is not the service; a look's finding is not recorded, and after a stop the engine looks again at once.
Why: The command line writes a round's message into its session before it calls the service, and retrying rounds through an outage filled a session with the same input again and again.

### decision the-retry-wait-is-a-call
The wait before a round that failed in passing is tried again is a call of the run that the engine makes and the clock answers at its time, its end counted from the failed round's end.
Why: Deciding then needs no clock, a wait made is known as made after a stop, and the work shows what it waits for and until when as for any call; deciding with the time as an input was turned down, since a decision could then not be taken again from the records alone.

### decision an-unread-return-is-sent-back
A return that could not be read is sent back to the agent in its session, as any return that does not meet the form, and counts against the run's limit of returns sent back.
Why: The agent's work is done and only its hand-in is wrong, so running the round from its start would pay for it twice. Repairing a text that is no JSON, in the engine or by a cheap model, was turned down: the agent that wrote it holds in its session what it meant, while a repair guesses at it (judgment, not measured).

### decision a-flagged-round-begins-a-new-session
A round the service's safety check flagged is given again at once in a new session of its line, whose name is worked out from how many of the line's rounds were flagged; flagged again in the same run, with only failures between, the work is paused.
Why: The same session would give the check the same context again, more likely the cause than the task's words, though that is a judgment no case has shown; a second flag says what the agent is given needs a look.

### decision a-note-run-is-held-only-by-its-own-pause
While a work is paused, a run that answers a note has its round after a failure held only where the engine paused the work since that round began, for its failure or for the budget it took the work over, which its carrier says before the round's end.
Why: A failure that is tried again by itself, or waits with every work, is no cause the owner must see first, and holding it would leave the note unanswered for as long as the owner's own pause lasts.
