Decision: Everything about an agent's session (which session a round runs in, what the session holds and is given, what each call cost, the command line it runs in, and keeping a waiting session warm) is one crate, the session manager (`crates/sessions`), which the engine calls before each agent round and between steps: the engine decides when (which cell runs next, when a work waits), the session manager decides and does the rest and records it in `sessions` and `pings`, instead of these pieces spread through the engine, because the owner wants all of an agent's context management in one place that can later move out of the engine's process.

Decision: A line starts a new session at its first round in a work, at the work's first round of a cell its line names in the flow's `starts` (the engineer's line at implementing, cell 4, and at fixing, cell 8), and at its next round once the context of its session (the prompt of the last call of its latest round, as recorded) is past the configuration's `agents.context_limit`, 500,000 tokens unless set; the session before ends, the worktree stays, and the new session is given everything its cell's round needs, as any session that holds nothing is; a return sent back is rewritten in the session that wrote it, and the limit takes effect at the round after; each session records why it started, instead of one session per line for the whole work that the command line compacts, because work 9's engineer session reached 312,000 tokens before implementing and 531,000 at its end, every call reading all of it again, while what implementing and fixing need is in the records the new session is given.

Decision: A line also starts a new session at its next round when the owner asks for one with the round's Start or Step, recorded as the owner's; a return sent back is then given whole with why it was sent back, since the new session does not hold it.

Decision: A line also starts a new session at its next round when the model its rounds run on changed (a tier's model changed, or the item moved to another tier), instead of resuming the session on the new model, because a model's prompt cache holds nothing of a session another model ran, so the whole session would be written again at the new model's price, while a new session is given only what its cell needs; no keep-warm ping goes to a session whose next round starts anew this way.

Decision: When a work waits (paused, held by the owner's pause of every work while the owner keeps sessions warm then, for the owner's or the architect's answer, or at a row that waits for other items) and every way from where it stands leads to a round in one line's session, the session manager sends that session one minimal message 55 minutes after its last call, while the command line's prompt cache still holds the session, and again every 55 minutes, at most 39 times in one wait; it sends none when that round will start a new session anyway (a cell its line starts one at, a session past the limit, or one the owner asked for), none while every work is paused and the owner switched keeping warm off, none beside a round of the session, which the engine's single thread makes impossible and the session manager checks, none once the cache has let the session go; a ping that failed is tried again a minute later; a ping holds no slot, instead of letting the cache expire, because a call after the hour writes the whole session again at forty times the price of reading it (work 9 paid $3.28 for two such rewrites), and 39 reads cost what one rewrite does. This works around the cache's one-hour lifetime.

Decision: A ping runs the command line of the session's last round exactly as it ran, resuming the session, with only the message changed, instead of a command line built from the configuration as it is now, because the cache is read only when everything that shapes the prompt (the command line, the model, the system prompt, the tools and the structured-output schema) is the same; a changed reasoning effort keeps it, unless it turns thinking on or off, as `low` does.

Decision: Each ping is recorded with the cell the work waited at and what it waited on (its pause, the owner, the architect, other items or a tool), and its cost as what the session's cost grew by, which the next round's cost leaves out; the anomalies command lists the pings and the work's cost on the page and in the cost command counts them, instead of a cost hidden in the next round or nowhere, because needing a ping means the work waited over an hour, which is an anomaly to fix where it comes from.

Decision: The session manager starts a round at the reasoning effort its cell declares in the flow, whatever the model the item's level picks, instead of an effort for each level, because the owner set the effort by the kind of task each cell is, and a level is only a model; changing an effort is a change to the flow. A changed effort between rounds of a session keeps its cache.

Decision: While a round runs, the session manager gives its command line two hooks (`--settings`): after each tool use, `wf-agents deliver` hands in the interjections waiting for the round's line, records them as delivered in the round, and the round's return is checked against them as against those its message gave; after a compaction, the session is given again at once what the round's cell is given as a session that holds nothing is sent it, from a file kept while the round runs; instead of interjections waiting for the next round and a compacted session carrying on without what it was given, because the flow says the session manager does both, and the command line adds a hook's output to the session where the agent is. A round that has ended takes no interjection, so a keep-warm ping, which runs that round's command line again, hands in none.

Decision: The session manager sets up a work's worktree and branch at the start cell, on a machine with a free slot (the first machine when none is), reports each machine's free slots from the works holding one, says whether a head a round hands in is the worktree's HEAD with nothing uncommitted, and ends a work's sessions at its end, where the worktree is removed and the branch stays, instead of the engine doing these beside its flow steps, because worktrees and sessions are what the session manager keeps for the works, and they are caches the database and the branch on GitHub can make again.

Rejected:
- One session per line, compacted by the command line: rejected because a session read again whole at every call grows the cost of each call with the work, and compaction keeps what the command line chooses, not what the cell needs.
- Pinging a session whose cache has expired, or without a cap: rejected because a ping after the hour writes the whole session again for nothing, and an endless wait would cost more in pings than the rewrite it saves.
