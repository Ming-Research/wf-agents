Decision: The owner's page follows GitHub's Primer design system (primer.style): every colour, type size, weight, spacing, radius and border width is a token of `@primer/primitives` (the functional tokens, such as `--fgColor-default`, `--text-title-shorthand-small` and `--base-size-8`), and every control and recurring part is the `@primer/react` component this spec maps it to, instead of values and parts the page made up view by view, because the owner found the page's look unreasoned (small grey bold labels used as headings) and asked for an industry model to copy and a spec that every later change keeps to.

Decision: Where Primer says nothing, the page decides in Primer's spirit, and each such rule here says "ours"; a value Primer has no token for is named once in the page's own token file, `client/src/styles/tokens.css`, beside the reason, instead of being written where it is used, because a value written twice drifts.

Decision: The page follows the system's light or dark appearance with Primer's light and dark themes: the root element carries `data-color-mode="auto" data-light-theme="light" data-dark-theme="dark"`, and the app is wrapped in `ThemeProvider` (from `@primer/react/next`, colorMode auto) and `BaseStyles`, instead of a switch of the page's own, because the owner sets the appearance once in the system, and one source of the mode keeps the tokens, the components and their overlays in step.

Decision: Type has six steps and no others, each from Primer's text tokens: the page's title is title medium (`--text-title-shorthand-medium`, 20px semibold); a section's heading is title small (`--text-title-shorthand-small`, 16px semibold); a sub-heading, the name of a part inside a section (such as "Why" or "Where this differs from the item as written"), is body medium semibold (`--text-body-size-medium`, `--base-text-weight-semibold`, 14px); body text is body medium (`--text-body-shorthand-medium`, 14px normal, line height 1.5); small text is body small (`--text-body-size-small`, 12px normal); code is `--fontStack-monospace` at `--text-codeBlock-size` in a block and `--text-codeInline-size` inline, because a few steps far enough apart read as an order at a glance, and Primer's steps are the ones GitHub's readers already know.

Decision: A heading is in the default foreground (`--fgColor-default`) and is either larger than what it heads or, at the same size, semibold; muted text (`--fgColor-muted`) is never bold and never a heading, and no label is small, muted and bold at once, instead of the small grey bold labels the page had over its fields and stages, because muting says "less important" while bold says "look here", and the owner read the two together as a contradiction.

Decision: Weight marks structure only: semibold (`--base-text-weight-semibold`) for headings, the head of a card, `strong` in text an agent wrote, and the one current choice (the view in the bar, the line of the checklist the work is at); medium only where a Primer component sets it itself (a Label); everything else normal; bold (700) is not used, because weight spent on decoration stops marking what is a heading.

Decision: Text an agent or the owner wrote reads as one document in the page's font, as GitHub's markdown reads (ours, after Primer's markdown style): body medium with line height 1.5, paragraphs and list items `--base-size-8` apart, lists indented `--base-size-24`, a heading the agent wrote drawn as a sub-heading whatever its level, inline code and code blocks as Primer's markdown draws them (`--bgColor-neutral-muted`, `--borderRadius-medium`), with no box, background or indent of its own, because the agent's headings must not outrank the page's own, and a box around prose says it is something else.

Decision: Colour comes only from Primer's functional colour tokens, never a hex value, a named colour or a colour the page mixes (`color-mix`): `--fgColor-default` for what is read, `--fgColor-muted` for facts about a thing (who wrote it, when, its round, a hint), `--fgColor-accent` for links and the place chosen; `--bgColor-default` for the page and its boxes, `--bgColor-inset` for the bar, `--bgColor-muted` for the head of a box, a card or a table, `--bgColor-neutral-muted` for code and a row under the pointer, `--bgColor-accent-muted` for the option or row picked; `--borderColor-default` round a box, a control or a table, `--borderColor-muted` for a line inside a box and the rule under a heading, because the functional tokens carry their meaning into both themes, and a colour picked by hand is right in one theme at most.

Decision: A state has one colour wherever it shows, through Primer's functional state tokens and a Label's variant: done, confirmed, merged and took are success; running and working are accent; waiting for someone, paused, sent back, queued, provisional and to check are attention; failed, cut off, stopped by the engine, ended, cancelled and disagreed are danger; new and anything else is secondary, because the owner learns a colour once and reads it on every view.

Decision: Spacing (margin, padding, gap) uses Primer's size scale only, `--base-size-4`, `-8`, `-12`, `-16`, `-24` and `-32` (and `-2` and `-6` only inside a control or a label, where Primer uses them), with this rhythm (ours): 4 between a name and its value and between marks on one line; 8 between paragraphs and the lines of a list and under a heading; 12 between the parts of a section and inside a box beside its text; 16 inside a card and round a pane's content; 24 between sections, because a fixed rhythm lets the eye group what belongs together without lines.

Decision: Corners are `--borderRadius-medium` for boxes, cards, controls and code, and `--borderRadius-full` for labels, counters and dots; lines are `--borderWidth-thin`, with `--borderWidth-thick` for a marked edge (the option recommended) and `--borderWidth-thicker` for an item's state edge in the tree; the page casts no shadow, and what floats over it uses Primer's `--shadow-floating-small`, because Primer's own components already draw with these, and the page's parts beside them must not look like another kit.

Decision: A reading page (an item, the settings) is one column at most `--breakpoint-large` wide (1012px, the width of Primer's large PageLayout) with `--base-size-24` round it (`--base-size-16` in a pane narrower than `--breakpoint-medium`); a view that is a chart or a list over the window (the works, the flow, an architect, the system) takes the whole width with `--base-size-16` round it, because prose wider than that is slow to read, while a chart and a wide table need every column.

Decision: The bar is one row 48px high, as tall as Primer's UnderlineNav, on `--bgColor-inset` with the nav's line under it (ours, after GitHub's header): the name `wf-agents` as title small, the views as an `UnderlineNav`, and at the right end the engine's state, its switch and keep-warm and the slots, instead of two rows (GitHub's header over its nav), because the flow's chart fills the window under the bar, and a second row would take its height.

Decision: A split between a list and what is picked from it (the items' tree and an item, the conversations and the one open, a chart and its docked column) is Primer's PageLayout with a resizable `PageLayout.Pane` whose width the browser keeps (`widthStorageKey`); where the split needs more than the pane gives (a double click that resets the width, a second divider in the column), it is ours and drawn as PageLayout's divider (a `--borderColor-default` line that turns `--borderColor-accent-emphasis` under the pointer), because one way to drag a split is learned once.

Decision: Each recurring thing has one part, and a new view uses it instead of drawing its own; the list follows, one thing to a line, and a thing not yet listed gets its line here before a view draws it, because "like things look alike" (Article 8) holds only if the mapping is written down and checked.

Decision: A view in the bar is an `UnderlineNav.Item`, the current one with `aria-current="page"` (Primer draws its text semibold and its underline); its counts are `CounterLabel`s, what waits for the owner `variant="primary"` and the rest secondary, because the views are the page's places, as a repository's tabs are on GitHub, and a count beside a view says what waits there before it is opened.

Decision: The engine's state in the bar is a `DotFillIcon` Octicon coloured by the state (`--fgColor-success` running, `--fgColor-attention` pausing, `--fgColor-muted` paused, `--fgColor-danger` offline or halted) before its words in body medium, the words of a halt in `--fgColor-danger`, because the owner reads whether anything runs at a glance, and the colour says it before the words.

Decision: A page's title and what it is about is a `PageHeader`: `PageHeader.Title` as the h1, its state as a `Label` in `PageHeader.TrailingVisual`, its facts in `PageHeader.Description` in body small `--fgColor-muted`, its controls in `PageHeader.Actions`, because every page that is about one thing opens alike, with what it is first and its state beside it.

Decision: A section of a page is ours on Primer's `Details`: one summary line holding a `ChevronRightIcon` or `ChevronDownIcon` in `--fgColor-muted`, the title as an h2 in title small, its count as a `CounterLabel`, and who wrote it in small `--fgColor-muted` text after them, with a `--borderColor-muted` rule under the line and `--base-size-24` before the next section; no box round it, instead of a box round each section, because a page of boxes read as a heap of separate things where the owner reads one document.

Decision: A part inside a section that folds (the approaches compared, earlier versions, why this one and not the others) is the same `Details` one step down: its title a sub-heading (h3), no rule, its body indented by the chevron's width, because a fold inside a section is a smaller thing of the same kind.

Decision: A labelled text, one field of what an agent handed back (Why, Cause, Where this differs from the item as written), is its name as a sub-heading (h3) over its text, `--base-size-4` between them and `--base-size-12` before the next, instead of a small grey bold label, because the name heads what follows it.

Decision: What an agent gave, exactly (a design card's and an ask's fields, a round's message and return), is a box: `--borderWidth-thin` `--borderColor-default`, `--borderRadius-medium`, `--base-size-8` `--base-size-12` inside, under the page's label for it as a sub-heading with its note beside it in small `--fgColor-muted`; a box means "exactly what the agent gave" and is used for nothing else, because the owner must tell the agent's words from the page's at a glance.

Decision: A card the owner rules on or answers (a design card, an ask) is drawn as GitHub draws a comment: a box with a head on `--bgColor-muted` holding its name semibold, its status as a `Label`, the round it came from and its small `--fgColor-muted` facts, then where it stands with the owner as a `Flash` (success when confirmed or answered, warning while it waits, danger when disagreed), then its body `--base-size-16` inside, because a card is something the owner answers, as a comment is on GitHub, and its head and band say where it stands before its body.

Decision: Options and approaches to choose from are ours: a box each, one under another, its name in title small over its fields, whose names are sub-headings; the one recommended carries a `Label` `variant="success"` and a `--borderWidth-thick` `--borderColor-success-emphasis` left edge; the one the owner picked a `Label` `variant="accent"`, a `--borderColor-accent-emphasis` outline and `--bgColor-accent-muted`; a box that can be picked turns `--bgColor-neutral-muted` under the pointer, because Primer has no card choice, and its colours for recommended and selected are these.

Decision: The state of an item, a work or a round, and a kind (of a ground, a deviation, a decision, an ask's point), is a `Label` in the variant its meaning has under the states above; a kind with no state meaning is `variant="secondary"`, and an ask's kind is coloured by its group with Primer's display colours (`--display-indigo-*` technical, `--display-teal-*` coordination, `--display-coral-*` owner only, `--display-yellow-*` environment) in a Label's shape (ours), because a state read in one colour on one page must mean the same on the next.

Decision: A count is a `CounterLabel`: `variant="primary"` for what waits for the owner, secondary otherwise; a count in a sentence stays words, because a count in a pill is read apart from the words round it, and the emphasis is kept for what the owner must act on.

Decision: A command is a `Button`: `variant="primary"` for the one action a form or view exists for (Start all, Send, Rule on the card), default for the rest, `variant="invisible"` for an action inside a line of text, `IconButton` with its `aria-label` for an action drawn as an icon; size small inside a row or a list, medium in the bar and in a form, because one primary button tells the owner which action a form exists for.

Decision: A setting that one click turns on or off (Keep warm) is a `ToggleSwitch` with its label beside it, size medium in the bar so that it is as tall as the button beside it, its On and Off words from the page's message catalog; one verdict of two that starts unset (confirm or disagree) is a `ButtonGroup` of small `Button`s, the one set marked by a leading `CheckIcon` and `aria-pressed`, instead of a `SegmentedControl`, which always shows one segment chosen; a choice from a short fixed list (an item's tier) is a `Select` size small; the words the owner writes are a `Textarea`, full width, resized only in height.

Decision: A link is Primer's `Link` (`--fgColor-accent`, underlined under the pointer; `muted` inside small text); a round's name and an item's number and title are links of this kind, an item's number in `--fgColor-muted` before its title in the colour of the text around it, because a link is recognised by its colour, and a muted link keeps small facts quiet.

Decision: A code the flow names a thing by (a cell's code, a row, a node's path) is `--fontStack-monospace` at `--text-codeInline-size` in the colour of the text round it, with no background and no weight of its own (ours, as GitHub writes a commit's hash), while code an agent wrote inline keeps the markdown code's background, because a cell's code beside its title is a name, not code to copy.

Decision: Label and value pairs are ours in Primer's spirit: a two-column grid, the name in body medium `--fgColor-muted` (never bold), the value in `--fgColor-default`, `--base-size-4` between rows and `--base-size-16` between the columns, because the value is what is read and the name only says which it is.

Decision: Who wrote something, when and in which round is one line of small text: who in `--fgColor-default` semibold when there is a who (as GitHub names a comment's author), the cell, the time and the round link in `--fgColor-muted`, `--base-size-8` apart, because who wrote something is read before when and where, and the rest is checked only now and then.

Decision: A list of objects that are read (what an item depends on, the notes under a line of the checklist) is rows one under another, `--base-size-8` apart, each its link first and its facts after it; a list of objects one opens (the items' tree, the conversations) is Primer's `TreeView` or `NavList`, with counts as trailing `CounterLabel`s, because a list is scanned by its first words, and a list one moves through is a navigation, not prose.

Decision: A table is ours in Primer DataTable's look: a `--borderColor-default` box with `--borderRadius-medium`, its header row on `--bgColor-muted` in body medium semibold `--fgColor-default`, its cells `--base-size-8` `--base-size-12` inside and lines of `--borderColor-muted` between rows, numbers right-aligned, instead of Primer DataTable's muted header, because a header is a heading and is not muted.

Decision: Tabs inside a view or a panel are Primer's `UnderlinePanels` (from `@primer/react/experimental`), each tab's count its `counter`; tabs that change the address are an `UnderlineNav`, because Primer's tabs carry the keyboard and the overflow a panel needs.

Decision: A number shown on its own (a work's cost, the asks to answer) is a tile, ours: what it counts in small `--fgColor-muted` text over the number in title medium and a line of small `--fgColor-muted` text under it, on `--bgColor-muted` with `--borderRadius-medium` and `--base-size-8` `--base-size-12` inside and no border, a tile that leads to its list turning `--bgColor-neutral-muted` under the pointer; the marks that draw numbers (bars, a stacked bar, columns) take their series' colours from Primer's data visualisation scale in one order (`--data-blue-color-emphasis`, then orange, green and purple) and what is none of them `--data-gray-color-muted`, the shares of a round's cost blue, orange and green wherever they show, with their legend's keys as dots, their labels small text and their tips Primer's tooltip colours (`--tooltip-bgColor`, `--tooltip-fgColor`), because a border would make a tile read as the box of an agent's words, and one order of hues lets a colour be learned once.

Decision: The owner's Start, Pause and Step of a work and the choice of a new session for them are small `IconButton`s, the choice an `IconButton` with `aria-pressed` drawn as the option picked (`--borderColor-accent-emphasis`, `--bgColor-accent-muted`, `--fgColor-accent`) while pressed; their icons are the page's own at Octicons' size (a triangle, two bars, a triangle against a bar, a speech bubble holding a plus), since Octicons has no step and no new session and draws play and pause in circles; what each does, or why it cannot now, is said on hovering, because the four are one set and must look it.

Decision: A choice of what a view shows from a list that grows (the flow's stored versions) is an `ActionMenu` whose button, size small, names what is shown ("Flow v12"), its items a single-selection `ActionList` with each one's facts as an `ActionList.Description` and the one in use a `Label` `variant="success"` as its trailing visual (as GitHub marks a release Latest), instead of a native select whose options carry the facts as characters, because the button reads as a name, and the facts belong to the moment of choosing.

Decision: Controls that float over a chart (the flow's version and Compare) are ours: one surface on `--overlay-bgColor` with a `--borderWidth-thin` `--borderColor-default` border, `--borderRadius-medium`, `--shadow-floating-small` and `--base-size-4` inside, its controls one size, `--base-size-8` apart, and what the chart floats in the same corner (its map) under it at a distance the surface's height sets; what floats over the whole page (Primer's menus and tooltips) is above the bar and the chart, at `--zIndex-dropdown`, because the chart is read under them, and a group of controls is one thing to the eye.

Decision: A panel docked beside a chart (a cell, a round, a rule, a store, a comparison) is ours: its head holds the way back as a small `Link` with an `ArrowLeftIcon` over its title, the title in title small (`h2`) with a code in it as a code is written and where it stands in `--fgColor-muted` at normal weight, who does it in small `--fgColor-muted` text, and its close an invisible small `IconButton` with an `XIcon` (or, where the panel stands in place of a list, an invisible small `Button` back to the list), a `--borderColor-default` line under the head and `--base-size-16` round what it holds, because a panel is a small page with a title, and its way out is in the same place on every one.

Decision: Events shown as one run in time (what passed in a conversation, the notices about a work) are Primer's `Timeline` (`Timeline.Item`, a `Timeline.Badge` holding the event's Octicon, `Timeline.Body`), and an entry of a conversation is a comment box as a card is (its head on `--bgColor-muted` with who to whom and when, its text as markdown under it); a history kept by kind (an item's earlier cards, asks and works) stays sections, one for each kind, because a run of events is read in time, while a history kept by kind is looked up by kind.

Decision: The page has no avatars, since nobody on it has a picture (ours): who is named in words, and where a mark helps tell the owner, an agent and the engine apart in a timeline or a conversation, it is an Octicon in a `Timeline.Badge` (`PersonIcon` the owner, `CpuIcon` the engine, `AgentIcon` an agent), instead of made-up pictures or initials, because those would read as people the page does not have.

Decision: A fold marker is `ChevronRightIcon` closed and `ChevronDownIcon` open, in `--fgColor-muted`; a done step is `CheckCircleFillIcon` in `--fgColor-success`, the current step `DotFillIcon` in `--fgColor-accent`, a step ahead `CircleIcon` in `--fgColor-muted`; how sure an agent is shows as five dots `--base-size-8` wide, filled `--fgColor-success` (ours), instead of characters (a tick, a triangle, a circle) whose size and weight follow the font.

Decision: Something the page tells the owner about the view itself (a request that failed, a work the engine stopped, an item cancelled) is a `Flash` in the variant of its meaning, and a hint beside a control is small `--fgColor-muted` text; loading is the words "Loading" in `--fgColor-muted`, because a notice about the page must not look like something an agent wrote.

Decision: A chart keeps its layout, shapes and lines as the page's decisions draw them (stage boxes, routed arrows with rounded bends and arches, circles, badges, the halo's three arcs), and only its look follows this spec: its text, borders and backgrounds use the functional tokens (`--fgColor-default` and `--fgColor-muted` for labels, `--borderColor-default` and `--borderColor-muted` for boxes and lines, `--bgColor-default`, `--bgColor-muted` and `--bgColor-inset` for fills), and its text the type steps at the sizes the owner set for reading it at full size: a cell's title body large (`--text-body-size-large`, 16px), its notes, the arrows' labels and the nodes beside the cells body medium (14px), a stage's name title small (16px semibold), codes monospace; text the layout measures is measured in the font the tokens give, read from the page at run time, instead of a font written in its code.

Decision: A chart's legend (its "?") and every panel that opens from it (a cell, a round, a rule, a store, a comparison) are ordinary page parts and use the components above, because the owner reads them as the rest of the page and must not learn a second look.

Decision: Charts are converted to this spec in a step of their own, after the owner has reviewed this spec and the item page; until then the chart's styles are among the parts not yet converted, because the owner reviews the rules before the chart changes.

Decision: A change to the page is checked against this spec by `npm run check:ui` in `client/`, a step of the `ci` workflow: it refuses, in the client's CSS and in its inline styles, a raw colour (hex, rgb, hsl, a named colour, `color-mix`), a raw font size, font shorthand or weight, a raw spacing value (a margin, padding or gap other than 0 or auto), a raw radius or border width, and a rule that makes muted text bold; a value is a `var()` of a Primer token or of the page's token file; the exceptions are the token file itself, the chart's named values, each with its reason, and the styles not yet converted, each named with the step that converts it, a list that only shrinks, because a rule that nothing checks drifts with each change, as the page's own look did.

Decision: What the check cannot see a reviewer checks against this spec: each thing on the page uses the part its line here maps it to; a heading is a heading element in the type step of its level; a box holds only what an agent gave; a new recurring thing gets its line here in the same change that first draws it, because which part a thing is, and whether a box holds an agent's words, is a judgment no pattern sees.

Rejected:
- The page's own colours, sizes and parts, tidied: rejected because they were chosen view by view with no rule to hold the next change to, which is how small grey bold labels came to head the item page.
- Primer CSS (`@primer/css`, class names on plain elements): rejected because the page is React, `@primer/react` carries the same look with the behaviour (focus, keyboard, overflow menus) built in, and Primer itself now ships its look through the React components and the primitives.
- Another system (Material, Fluent, Ant Design): rejected because the owner chose GitHub Primer, whose look the owner reads every day on GitHub, and whose dense, text-first pages fit a page that is mostly what agents wrote.
