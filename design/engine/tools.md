Decision: A query's rows reach the agent, and the round's record, as a list of objects, each with a field for each column, and rows too long to give inline are saved one JSON object per line and given by the path in a field of their own, instead of one text of JSON lines inside the result, because a text inside JSON escapes every quote of every row, which the agent then reads through; the flow's schema for the tool cell's return says so, a row being an object with no fields listed, which holds whatever fields its value has, since the engine checks its own tool cell's return against that schema.

Decision: A red check's log tail is given without what gh puts before every line (the job, the step and the time) and without the escapes that colour the text, which gh writes with the escape character as the two characters "^[", because those take most of each line and say nothing about why the check is red; the times of the named tests are read from the logs cleaned the same way.

Decision: The ci tool gives, for each test the agent named, the time of the whole test binary that holds it, read from the fast CI's logs and said as the binary's time with how many tests it ran, or that the test was not found there, instead of no times at all, because stable `cargo test` times no test on its own, and without a time the agent fetched the whole job log to find one; the flow still says each test's own time, since changing its words changes the flow's digest, and the engine's words in each time say what the time is.

Decision: Before a tool cell runs, the next round's preview lists what each tool asked for will do (which head ci pushes and which tests it names, the gh command, the query), because the owner presses Step to run exactly that, and a note about an agent's round on the owner's account says nothing about it.

Decision: `wf-agents tree-check <fork point>` is a design tree check a project can name as its `design_check`: it counts the design tree under a directory (`design` unless `--root` says another) at HEAD, its nodes (the Markdown files), their depth below the root and the decisions (the paragraphs that start "Decision:"), and how many more of each than at the fork point, because the design tree review is to be given those numbers, and without a check named nothing printed them.
