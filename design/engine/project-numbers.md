Decision: The engine measures how many of a project's works run together from the rounds of the engineer's works on the project's items, counting a work as running only while it has a round under way that is not a wait for an answer (the cells that ask the owner or the architect, whose round stays open for the whole wait, and under that cell's ids in every flow version), apart from the architect's works, instead of every round under way, because the round of a work waiting for the owner or the architect stays open for as long as the answer takes, so that counting all rounds reports works as running together when none ran, which is the opposite of what the policy's signal about parallel running needs to show. A round of a tool cell counts as running for now, provisionally: a work waiting for CI holds its slot, and the count can be reopened if the owner wants it apart.

Decision: The cells counted as a wait for an answer are the cells of the engineer's graph whose step asks the owner or the architect, and a test holds the list the measure excludes to what the flow says, instead of a list that only the measure knows, because a cell added to the flow that waits for an answer would otherwise be counted as running without any check failing.

Decision: A work stopped before the end of its graph records the kind of its end, in a column of its own written in the same update as the text, from a kind its caller names where the end is written (the item cancelled, the flow moved to a new version, the work started over, other), and the engine counts, for each week, the engineer's works of the project that ended without their item being merged by this work, each once and by that kind, instead of reading the kind back from the text the works table records, or counting items, because a category read back out of prose exists only because it was never kept, the text carries a version number and a clause that differ for every flow move so that it names a kind only by its start, and one place writes every end, so that it can make every caller name its kind. A work that reached the end of its graph without a merged round counts under a kind of its own, derived from its rounds because it records no stop; the one such end the flow has is a work whose architect gave all of it to sub-items, which the end cell waits for instead of merging, while a work that delivers a report is merged through a pull request as one that delivers a change is, and has its merged round. A work with a merged round never counts, even when its item was cancelled after it, because it ended by its merge. The kinds of works already stopped are filled in once by the migration from the start of their text.

Decision: A week in which nothing ran or ended shows zero for each of these numbers, not a missing value, and the weeks are those the project's other numbers use, instead of a week of its own, because the policy's signals compare these numbers week by week with the others.

Rejected:
- The history of which works run, kept in a table of its own: rejected because it needs a write at every place a work starts, waits, pauses or ends, and weeks before it would be empty, while the rounds and the changes already say what the first number needs.
- Rebuilding each work's running stretches from the changes to its cell and its pause: rejected because it replays every change of every work to reach what the cell of an open round already tells, and an older flow version's cell would have to be read by a second rule.
- The kind read back from the start of the text, with the text built and read by one function: rejected because it is still a category recovered from prose, and a writer that does not go through that function is counted as other without anything failing.
- The text of the end replaced by an object holding the kind and the text: rejected because every place that reads the text or tests it for being set would change for nothing a column of its own does not give.
