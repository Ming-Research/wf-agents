Decision new-session-points: A line starts a new session at its first round in a work, but for the architect's line, which takes up there the session the project's previous architect work left unless it ended, at the work's first round of a cell a row of the flow leads to with the action `open_session` (the engineer's line at implementing, cell `I1`, and at fixing, cell `T6`; the review of a batch, `B2`; the search, `X2`), which the chart draws on those rows, and at its next round once the context of its session (the prompt of the last call of its latest round, as recorded) is past the configuration's `agents.context_limit`, 500,000 tokens unless set; the session before ends, the worktree stays, and the new session is given everything its cell's round needs, as any session that holds nothing is; a return sent back is rewritten in the session that wrote it, and the limit takes effect at the round after; each session records why it started, instead of one session per line for the whole work that the command line compacts, because work 9's engineer session reached 312,000 tokens before implementing and 531,000 at its end, every call reading all of it again, while what implementing and fixing need is in the records the new session is given.

Decision keep-warm: While a work goes on or waits (paused, held by the owner's pause of every work while the owner keeps sessions warm then, for the owner's or the architect's answer, or at a row that waits for other items), each session of a line of the work that the flow can come back to is kept warm: the engine walks every way from where the work stands, through the cells of other lines, the engine's, the tools' and the owner's, and a line comes back at an agent's cell of its own that a way reaches before any of its cells where the flow opens it a new session (the work's first round at a cell a row leads to with `open_session`), where the session it has going on ends; a line no way reaches, or reaches only past such a cell, is behind the work for good, as every line is at the work's end. The session manager sends such a session one minimal message 55 minutes after its last call, while the command line's prompt cache still holds it, and again every 55 minutes, at most as many times in one wait as their reads cost no more than writing the session again for an hour would beyond reading it, at the prices of the session's model (`cost::prices`): 39 on Opus 5.5 and Sonnet 5.5, whose write costs forty reads, 19 on Haiku 5.5 (twenty), 79 on Fable 5.1 (eighty), none on a model with no prices; it sends none when the line's next round will start a new session anyway (a session past the limit, on another model or under another login account, or one the owner asked for), none while every work is paused and the owner switched keeping warm off, none beside a round of the session, which the engine's single thread makes impossible and the session manager checks, none once the cache has let the session go; a ping that failed is tried again a minute later; a ping holds no slot. Instead of letting the cache expire, because a call after the hour writes the whole session again; instead of keeping warm only the session of a waiting work's next round, because in the sixth trial the review's and adversarial testing's sessions sat idle while the engineer fixed and the CI ran, and four such waits (the table review 159 and 67 minutes, adversarial testing 147, choosing the way on 88) wrote 508,000 tokens again; and instead of 39 pings on every model, because a read is not the same part of a write on every model, so that on Haiku 5.5 the pings cost more than the write they save and on Fable 5.1 they stopped long before. This works around the cache's one-hour lifetime.

Rejected:
- Pinging a session whose cache has expired, or without a cap: rejected because a ping after the hour writes the whole session again for nothing, and an endless wait would cost more in pings than the rewrite it saves.

Decision ping-command-line: A ping runs the command line of the session's last round exactly as it ran, resuming the session, with only the message changed, instead of a command line built from the configuration as it is now, because the cache is read only when everything that shapes the prompt (the command line, the model, the system prompt, the tools and the structured-output schema) is the same; a changed reasoning effort keeps it while thinking stays on.

Decision cache-miss-measure: A round that resumes its session within the cache's hour since the session's last call, a round's or a ping's, and whose first call still reads from the cache less than half of what the session held (the last prompt of its round before, as recorded, so that a round that reads only a small fixed part such as the system prompt counts too) missed the cache; the round's usage record keeps what its first call read and wrote (`first_call`), from the command line's stream, since the result the command line reports at the end gives only the whole run's tokens and its last call's. What the round wrote to the cache is not the measure, because it is also what the session gained since, the last answer of the round before and the round's own message: in a trial two rounds of the policy line after a round of tools read all 32,208 and 69,003 tokens their sessions held and wrote 18,304 and 45,129 new ones, which a measure by what was written reported as misses.

Decision cache-miss-notice: The session manager tells a miss with the tokens of the session its first call did not read, what writing them again cost beyond reading them, and the parts of the command line and the variables of its environment that differ from the session's round before, or that none does; the environment a round's record keeps is the variables the engine sets and those the command line reads that it inherits from the engine's own, a secret only by its digest, since the command line inherits the engine's whole environment and a variable there can change its prompt. Decision cache-miss-by-design: A miss after what comes before the session's messages in the prompt changed since the session's round before (the model; the tools, among which the command line gives the envelope's schema, `--json-schema`, and those `--tools` names or `--disallowedTools` takes away by name; the command line's own version, whose system prompt and tools come first) is the command line writing the whole session again by design, and no fault: the engine keeps it in `cache_misses` with what it wrote again and cost, and with no notice, and the owner's numbers count only the misses that are faults; instead of a fault told to the owner, because in the sixth trial a work that moved to a new flow version, whose envelope had changed, and the architect's session after it were each reported as a fault of wf-agents, the architect's having written 123,000 tokens again, where the cost was that of changing the flow and nothing was broken.
