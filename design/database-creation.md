Decision: A database is made only by the explicit command `wf-agents init`, which runs only on a data directory that already passes the data-directory check (a git repository with a commit and a valid committed configuration) and refuses a place that already holds a database; every other command, the engine included, opens an existing database and fails with an error that names its path when there is none, because the files cannot tell a first use from a mistaken path (a fresh clone of the data repository has no database by design, since the database directory is kept out of git), so only a deliberate act separates the two, and then a missing database is always an error and creation never happens by accident.

Decision: The database layer has separate constructors with opposite refusals, one that creates and refuses a place that already holds a database, one that opens and refuses a place that holds none (an empty leftover file counts as none, and creating accepts it, so an interrupted create can be repeated), instead of one constructor that creates, migrates and opens for every caller, because the caller's intent then reads at the call site and no caller can create without asking to.

Rejected:
- Only the engine creates it: rejected because a pass of the engine would be needed before the first item can be added, a command meant for taking works would double as initialisation, and the engine itself would still create a stray database silently in a valid data directory that has none.
- Creation stays with the commands that already check the configuration (adding an item, starting the engine): rejected because those commands would still create silently in a valid data directory that has no database, such as a second clone, so an item could be written into a database the engine never reads; it shrinks the places that create but keeps creation implicit, where the chosen way makes every creation a deliberate act.
- A creation option on those commands: rejected because it is the same explicit act in an irregular shape: an option meaningful on only some commands, ties creation to commands that do other work, and tends to be copied into scripts and aliases until it protects nothing.
- Check only that the path is a data directory and leave creation as it is: rejected because it does not touch a data directory that has no database, it makes read-only views fail when the configuration is broken, and it leaves one constructor doing three jobs.
