Decision: `flow/flow.json` is the only definition of the flow, written in English, and it says nothing about any project: every project-specific value is a slot the project's configuration fills, because the same flow must run any project, wf-agents included.

Decision: The flow is compiled by the Rust crate `flow`, which the engine and the command line both use: it expands the shared rows, the gates and the asking block, builds each cell's return schema for each line, and runs every check on the flow (formats and names, every state the engine can be in is reached, each possible return takes exactly one row, every recorded value is read, every loop has a counter, every input has a source, every rule is used, the samples match); the expanded flow and its hash are stored as a flow version, because a flow that fails a check must never reach a running work.

Decision: A field of a return counts as read when a cell's input, a row, a check, an action or the cell's handoff reads it, when the cell marks it as shown on the item, which the owner's page then shows, or when the flow says which role an agent may ask reads it outside the flow, through the database, as the architect reads side reports; a field read in none of these ways is taken out of the return; what a cell does every time it returns is an action, never a database view the field is written into, because the owner reads the item and the architect the side reports, while a view named only as a note let a field nothing reads pass the check that every field is read.

Decision: The language each field of an agent's return is written in is said in the return's schema, and in no rule: every field is in English, as is everything that goes into the repository (commit messages, the PR's title and description); a field shown on the item, the design card with what changed from the card it replaces, and what an ask of the owner says (each point's what and what was tried, and the choice) are in the owner's language, `owner.language`, with technical terms in their English original, because the agent writes a field by its description, and what is read in the repository and by agents is English while what the owner reads is in the owner's language.

Decision: A design card that replaces an earlier one of its work says, in a sentence or two the round that hands it in writes beside it, what changed from the card it replaces and why, and the engine keeps it with the new card, instead of the owner comparing the two cards, because cards that replace one another look alike and the owner reads a replaced card only as what replaced it.

Decision: The owner rules on each decision of a design card, confirming it, disagreeing with it saying why, or choosing another of its approaches, and sends the verdicts on all of them in one ruling; the card is confirmed only when every decision is, and the decisions disagreed with reach the work each with the approach chosen and why, instead of one verdict on the whole card, because a card holds several decisions and the owner may disagree with one of them only.

Decision: A work is pinned to the flow version it started with, and is never moved onto another; when the flow moves to a new version, the works still running on an older one stop and their items start again on the new one (design/engine/half-done-work.md), because changing the flow under a running work could leave it in a cell or a state the new flow no longer has, and a work that ran on to its end would follow a flow that is no longer the flow.

Rejected:
- Project names, branches or rules written into the flow: rejected because the flow would then work for one project only.
