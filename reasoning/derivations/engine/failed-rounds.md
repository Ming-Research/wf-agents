Decision failure-rows: A return sent back and a run that ended without a return are shared rows every agent's cell has, which the compiler gives each agent's cell from the flow's rounds section and which come back to the cell itself: a return sent back, the third of the cell's returns in a row sent back (which pauses the work first), and one for each kind of failed run, named after it; no return takes them, and the engine takes them itself; instead of handling them beside the cells' tables, because the chart and the transition table then show everything that can happen at a cell, and one section of the flow says each once for every cell.

Rejected:
- Writing these rows into each cell of the flow, or into the shared rows by hand: rejected because they are the same for every agent's cell and follow from the rounds section's numbers and kinds, so writing them again could only let the two disagree.

Decision failed-run-not-sent-back: A round whose agent command line fails to hand in a return is not a return sent back and is never counted with returns sent back, because nothing was wrong with what the agent did: it never ran to the end.

Rejected:
- Treating a failed run as a return sent back: rejected because it tells the agent its return was wrong when there was none, and after three failures in a row pauses the work for a cause outside it.

Decision sent-back-new-session: The round after a return sent back that runs in a new session, as every round of a cell on no line does, is given the whole message and why the return before was sent back, instead of a new session told nothing of why, because a reader on no line sent back for its form handed in the same form again.

Decision failed-run-kind-only: The round after a run that ended without a return is told only the kind of failed run, never what the command line reported, instead of a report quoted whole, because the report of a failed run quoted the first part of the return it could not take, which showed one new architect's reading to the next, who must read the text alone.

Rests on: C:information, F:failed-run-report-quotes

Decision null-as-absent: Before a return is checked against its cell's schema, a field the flow lets it leave out that it holds as null is taken as left out, at every depth, instead of sending the return back, because an agent writes null for a field it has nothing for (`H7` wrote `waits: null` and its whole answer was sent back), and the two mean the same.

Rests on: C:efficient, F:agent-writes-null

Decision json-string-forms: A return whose field of the forms holds a string holding the JSON of an object is taken with that object, and its round records that it was (`engine.taken_from_text` in its input), so that how often models still write it shows; a run the command line gave up on because it refused such an attempt is taken from that last attempt within its round, as is any whole attempt it refused (`as_it_is` in `engine.unparsed`); instead of the round failing or the return being sent back for it, because in the fourth trial models wrote the form so in three rounds in a row, every attempt rewriting the whole return, while the form was all there. It works around how the model writes a field it is given no fields of, which the command line's schema now gives (see the agent command line's node), and goes once the record shows no model writing it. A string whose object is followed by closing brackets alone is taken the same way, those brackets dropped, recorded and counted with the rest: the model wrote the form as an object with a closing brace too many, whose JSON did not parse, so that it reached the command line as a string of that text, refused with `/outcome: must be object`, which told the model nothing it saw (in the engineer's trial every such attempt of cell D2, in R18-5, R18-10 and R18-11, ended so, and R18-5 and R18-10 were sent back for it, $0.27 and $0.18; tried with haiku on the command line 2.1.312, a form written with a brace too many reached it as a string). Every return is taken this one way, whichever way it came, the command line's, an attempt taken as it is, closed, repaired or handed in again, and a repair is checked as the return it gives is taken, so that a repaired return whose form is the JSON text of it is not refused for it.

Decision global-failure-wait: When the account's usage limit is reached, the network cannot be reached, the login has expired or the command line cannot be found, the engine starts no new round for any work and tells the owner once; it waits until the time the command line gives for the limit to reset, and otherwise lets one round try every half minute, then carries on each work from the cell it recorded, and the owner, who logs in again or installs the command line, writes nothing; instead of retrying each round, or pausing the work and asking the owner for a written answer, because one cause stops every work alike, only its passing matters, and the round that runs again is the proof that it passed.

Rests on: C:efficient, F:global-failure-stops-all

Rejected:
- Retrying every failure twice, then asking: rejected because a usage limit or a network outage then uses up every work's retries at once and asks the owner once per work for a single cause.
- Asking the owner for a written answer when the login has expired or the command line cannot be found: rejected because the owner has nothing to write; logging in again or installing is the whole answer, and the engine can see it by trying a round.

Decision transient-failure-retry: When the service is overloaded, returns a server error or times out, or the command line crashes, the engine runs the same round again, after ten seconds the first time and then after waits that double up to five minutes, until it passes, and records each attempt on the work, because these failures pass, and a round that waits longer each time costs nothing while it waits.

Rests on: C:efficient, F:transient-failures-pass

Decision unparsed-repair: A return the command line gave up on after its attempts at it, refusing each because the JSON the agent wrote could not be parsed or does not fit the command line's schema (`error_max_structured_output_retries`, the kind `unparsed`, handled by repairing), is not a passing failure, and its round never runs again from its start: within the round the engine first takes the last attempt as it is when its text is whole JSON, which has no syntax to repair, as any return; else closes the last attempt's text itself when a scan of its brackets outside strings shows it lacks only those that close it at its end; then has the installation's lowest level repair any other fault of its syntax, once, in a new session with no tools, taking the repair only when it parses, passes the cell's schema and checks, and keeps every other character, compared as characters since the original cannot be parsed (each escape read as its character, every character JSON's syntax uses and all whitespace left out of both, the rest the same in the same order); then resumes the agent's own session and asks it to hand its return in again, saying its JSON could not be parsed and that quotes and newlines inside a text must be escaped; and when none gives a return, pauses the work and tells the owner. A text cut off, shorter than the command line reported it (its count is of characters) or not ending in a closing brace, is never closed or repaired, and none rebuilt goes straight to the agent. Whatever comes of it is then taken as any return, and sent back when it does not fit. The round's record keeps each attempt's whole text and what each way came to (`engine.unparsed` in its input), and its cost holds the repair's and the hand-in again's, instead of rerunning the round, because one such round in a trial cost $0.33 rerun whole, and every later attempt re-read the whole session, 190,000 to 230,000 tokens each.

Rests on: C:efficient, F:trial-unparsed-rerun

Decision structured-output-settings: The command line's attempts at a return are made cheap to repair and few: every agent's command line runs with the stream's partial messages (`--include-partial-messages`), from which each StructuredOutput input is rebuilt whole and kept when it could not be parsed, the command line keeping only the first 2,048 characters of it in its session; with each tool input streamed whole (`CLAUDE_CODE_ENABLE_FINE_GRAINED_TOOL_STREAMING=0`), so that the service checks its JSON; and with three attempts instead of five (`MAX_STRUCTURED_OUTPUT_RETRIES=3`), because each attempt writes the whole return again. The schema the command line is given lists the short fields every return holds first and the field the forms are under last, as the format and every example do, so that after the long answer only closing brackets are left to write.

Rests on: C:efficient, F:cli-keeps-2048, F:whole-streaming-checked, F:attempt-rewrites-return, D:unparsed-repair

Decision cli-schema-per-line: The schema the command line is given, one for each line, refuses what no agent's cell of the line takes, as far as types and fields tell: it requires the fields every agent's cell of the line requires (`tell_owner` on the engineer's and the architect's lines, `flow_feedback`, and the engineer's graph's `side_reports`; not `progress`, which `tools` leaves out), and each object, the field of the forms included, requires what all its alternatives require and takes no field beyond those it lists when none of them does. The command line refuses such a return saying where and why, in the words of its validator (`root: must have required property 'tell_owner'`, `/outcome/take: must NOT have additional properties ('effects' is not allowed)`), and the model hands it in again within the run. Each attempt it refused in a run that handed a return in at last is kept on the round by why (`engine.refused` in its input), so that the record still shows these faults; when it gives up, the last attempt is taken as any return (see above), the engine moving a field every return holds up from inside the field of the forms. Instead of a schema that requires only the field of the forms and refuses nothing but a value of another type, because what passes the command line and fails the cell's schema costs a round sent back: in a trial of the architect one round (R10-2, cell U1) handed in no `tell_owner` and another (R10-14, cell H5) wrote `effects` inside `take` instead of beside it, the content right, each sent back and run again. A refusal within the run costs about what a round sent back costs the model, one more call that reads the session from the cache and writes the return again (tried with Haiku: 4,763 tokens read, 212 written, 255 put out, against 4,737, 316 and 275 for the same return sent back in a resumed session), without the round: the command line's start, the engine's message, and the count toward pausing a work whose returns are sent back again and again. A required field also makes the omission rarer: Haiku, told to hand in a given input that lacked one, added it unasked. The lenient schema had replaced, on 10-29, one that required the fields beside the forms' at the root and refused them inside with `not`, because the model put them inside at every attempt, refused without being told why; the command line of version 2.1.312, tried, says where and why for a missing field and for a field where it does not belong, the model, told to put right what it refuses, put both right at its next attempt, and the short fields now come first. The schema changing changes what every session's prompt holds, so every session's prompt cache is written afresh once. It is one for each line instead of one for each graph, since a session is a line's, so that it is still the same for every round of a session, and a field only some lines' returns hold (`tell_owner`) is not offered to the agents of the others, whose returns holding it the engine would send back.

Rests on: C:efficient, C:problem-first, F:trial-architect-misplaced-fields, F:refusal-cost, F:required-field-added, F:cli-validator-where, F:cache-same-prompt, F:prefix-change-rewrites

Decision form-if-then: Inside the field of the forms, each form that has a field no other form of the graph has is told apart by it, and then requires what that form requires and takes no field it does not take (an `allOf` of an `if` and a `then` for each such form), so that a cell's own answer without a field it requires is refused within the run naming the field, instead of being sent back by the engine: in the engineer's trial a return of cell D2 without `why`, which only D2's answer has and which the shape of every form taken together cannot require, passed the command line and was sent back, a round of $0.34 (R18-6). The command line 2.1.312, tried with haiku, refuses it with `/outcome: must have required property 'why', /outcome: must match "then" schema` and takes the answer with `why`. A form all of whose fields other forms have too (the engineer's I1, whose fields T6's form has as well, T5, whose `columns` T4's has, the architect's U1, whose `notebook` most of its forms have) is checked by the shape of every form taken together alone, as before, since which form a return of it is cannot be told from its fields. The rules made the schema of the engineer's graph 15,657 bytes and the architect's 15,191, against 11,893 and 11,246, measured on the trial's flow; the same for every cell of a graph, they cost the cache nothing beyond the one rewrite a changed schema costs.

Rejected:

Decision prompt-too-long-pause: When the prompt is too long for the model, the engine pauses the work and tells the owner at once, and runs the same cell again once the owner lets the work go on, because running it again cannot help: it is a defect of the engine's to fix.

Decision engine-pause: Whatever the engine pauses a work for (a prompt too long, returns sent back too often, a step it cannot take, such as its own tool cell's return that does not fit the flow), it tells the owner once, the pause is the engine's, which the owner's Start all leaves until the owner starts that work on its own, and it closes the round the pause left open with the reason, as a run that ended without a return, so the round shows as what it was and the cell runs again as a new round once the owner lets the work go on; a round an earlier engine left open when it paused is closed the same way, with the reason the work was paused, when the work goes on; instead of a paused work the owner hears nothing of and a round shown as running for ever, because a pause waits for the owner, and the owner can only act on what the owner is told.

Decision design-path-attempts: A cell that may not change the design paths counts the change from where the attempts of it that came just before began, each sent back, cut off or failed, and the reason it is sent back says which part is whose: what this round committed, the commits an earlier attempt made and left on the branch (named, with the word to revert them), and what is not committed, instead of counting from this round's start alone and saying "this round changed the design paths" for a change an earlier attempt left, because a change a sent-back attempt made is not accepted by being left on the branch, and an agent told it made a change it did not make takes the reason for a mistake and is sent back again; a revert in this round that undoes them leaves no change, and the return is taken. The flow's words for the check say "in this round"; its digest is kept, so the engine's reason says what was counted.
