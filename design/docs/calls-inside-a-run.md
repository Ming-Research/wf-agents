# Calls inside a run

What a cell asks for while it runs, and what the flow requires of what it returns. The engine makes the calls an agent
asks for, the owner's letting a run go on at a limit, and the wait for the clock; the calls a flow declares on a cell,
which the engine makes without being asked, are not built.

1. What a cell asks for while it runs (a tool), and what the flow requires its return to meet (the engine's checks, a
   review that only advises), are calls of that run: the run rests at the call, the result comes back into its next
   round, and the run finishes when its return has met them. A cell that cannot go on asks the owner a question, which
   is no call (the design of data and context, 34).

2. A call holds no place in the order of cells. What it asks and what it gives back are data of the work (the design of
   data and context, 27 and 28). The flow declares it on the cell, and the chart draws it beside the cell.

3. A call the flow requires is made by the engine, never left to the agent to ask for: what a task only asks of an
   agent, the agent may leave undone.

4. The owner's letting a run go on at a limit is a call of that run too, whose result is only that the run goes on.

Drawn as cells, three kinds of call took some thirty-seven of an engineer's graph's ninety-four rows, the same three
on every agent cell, and the engine kept a stack of who had called whom; where a work was then had two answers, the
tool's cell and the cell the tool ran for.
