Decision: The README names every command of the `wf-agents` command and every entry of the data directory, and a test fails when it does not, when it names a subcommand or long option that does not exist, or when `wf-agents` starts a command anywhere the test does not read, instead of a README that nothing checks, because the commands change with almost every change to the engine, so a README written by hand and checked by nobody is wrong soon after it is written.

Decision: The test reads command lines by one convention (a command line is a code span that stays on one line, or a line of a fenced block, that begins with `wf-agents` after an optional shell prompt and holds no quote or shell operator) and reports every other place where `wf-agents` starts a command, instead of reading every way a shell or Markdown can write a command, because a reader for all of them approaches a parser of both with no end, each new spelling another case to keep, while one convention and a report of everything else gives the same protection with a reader small enough to keep and lets no wrong command pass unseen.

Decision: The README holds only what `--help` cannot hold (how to start and stop the engine, the order the owner's commands are used in, and what the data directory holds) and leaves what each argument means to the command's own help, which the test requires every argument to have, instead of repeating each command's arguments in the README, because a description written in two places has to be kept equal by hand, while one written beside the command changes with it.

Rejected:
- Generating the command reference into the README and checking the generated block against the commands: rejected because it copies the help into a README that then defines the same thing twice and grows past what the owner reads it for, the order of use, and it leaves the commands that the prose names unchecked.
- Writing the guide to the commands as the command's help text and pointing the README at it: rejected because answering an ask of the owner and ruling on a design card is longer than a help text suits, and a reader who has the repository looks in the README first, while the help is kept for each command's own description.
