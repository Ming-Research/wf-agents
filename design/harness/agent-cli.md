Decision: An agent's round runs as one call of an agent command line in its print mode (`claude -p` and the like), resumed in the same session for the next round, instead of an agent software development kit, because the owner can then switch accounts in a terminal and switch to another vendor's command line, and which command line runs and how it starts is configuration.

Decision: Each line of a work (the engineer, the review, the adversarial tester, the advisor) goes on in its session, which the command line compacts itself when it fills within a round, and the session manager starts the line a new session where the flow says (the engineer's at implementing and at fixing) and once its session's context is past the configuration's limit, instead of one session per line for the whole work, because a session read again whole at every call grows the cost of each call with the work (see the session manager's node).

Decision: The command line is given one structured-output schema that is the same for every cell (the return's top-level fields with their types), while the cell's own schema goes in the prompt and the engine checks the return against it and says where it does not fit, instead of the cell's schema as the command line's structured-output schema, because the command line places that schema with the tool definitions, so a schema that changes from cell to cell invalidates the prompt cache at every change of cell.

Decision: An agent asks for the GitHub and database query tools by handing in `tools`, which the engine runs in its tool cell and gives back in the next round, instead of tools the agent calls in the middle of a round, because to the model either is one tool call, and going through the tool cell records every run and checks it against the list of allowed commands.

Decision: The command line reads only the settings of the agents' own configuration directory (`--setting-sources user` for `claude`), so it reads no project instructions or project settings by itself, such as the worktree's AGENTS.md, instead of reading them as a session started in a project directory does, because the engine gives the project's guide as a material once in a session, and a guide the command line reads by itself comes twice and comes back in every session whether the session needs it or not.

Decision: What the agents of each line may not do on the machine is in the installation's configuration, with defaults, and every round's command line refuses it as tools and commands: no line runs heavy work (compiling, type checking, building, test suites, benchmarks, measurements: cargo, rustc, make, tsc, npm runs, npx and the like) or pushes, and the review and the advisor only read, editing no file and committing nothing, instead of the command line's arguments refusing a few commands for every line alike, because heavy work goes to CI however convenient running it here looks, and a role that only reads must not be able to change the work it reads.

Rejected:
- Starting the command line bare (`--bare`), which also reads no project instructions: rejected because it takes only an API key, not the account the owner logged in with.
- A structured-output schema of a bare object: rejected because the model then handed in the nested objects as JSON strings, seen on three returns in a row.
- Tools served to the agent in the middle of a round: rejected because it saves the model nothing, and the costs of handing back (fields a return must carry, a restart of the command line) belong to how a return is handed in and can be cut there.

Decision: The directories outside the worktree where the engine saves what it gives agents by path (`tool-output`, a tool's result too long to give inline, and `logs`, the logs of red checks) are added to every round's command line with `--add-dir`, by their real paths, and edits there are refused with `--disallowedTools "Edit(/<path>/**)"`, a path that starts with two slashes being absolute and an Edit rule covering every tool that edits a file, instead of paths the agent was given and could not open, because Claude Code lets its tools reach only its working directories, and a result the agent cannot read is no result. This works around the command line's permission model, which has no read-only working directory: `--add-dir` lets its tools read and edit there, and in the `acceptEdits` mode its own filesystem commands (mkdir, touch, rm, rmdir, mv, cp, sed) run there without asking; the Edit rule refuses the file-editing tools and writes Claude Code recognises (such as tee and redirections), but not those commands, which a rule on a path does not reach. So an agent can read every file in those two directories, and can still copy, move or delete one there with a shell command, though not edit it with a tool.

Decision: The architect's line only reads, as the review and the advisor do, and its command line runs in a directory of its own under the worktrees, with every project's checkout added to what it may read, instead of a worktree of one project, because the architect looks across every project and changes the code of none: what it changes, it changes through the engine.
