Decision: An agent round's inputs are of two kinds, always and conditional: the always inputs (the cell's task, what the agent reads itself, the addresses of the conditional inputs to work from under the number of each of the cell's inputs, why the round happens and which format to hand in) are given every time the cell is entered, even word for word as the last time, while each conditional input (rules, the item, settings, the repository guide, other cells' and engine steps' outputs, tool results, replies, interjections, return formats, what each numbered input is, the worktree) is given when the session does not hold it and referred to by its address when it does, because the always inputs steer the round, while a conditional input repeated to a session that holds it spends its context and hides what is new.

Decision: After a return sent back, the message says only why it was sent back and that the return is to be rewritten, with its format's address, and gives and refers to nothing else, instead of the whole message again, because the agent did the work and holds everything it was given; only the return was wrong, and giving the task again tells it to do the work again.

Decision: What each of a cell's inputs is, as the flow describes it, is the conditional input `inputs:<cell>`, given once in a session for each flow version, and the always inputs list only each input's number with its addresses; what the agent reads itself is said in full, since the description is the whole of that input; instead of each input's description beside its addresses every round, because the descriptions do not change within a flow version and were most of the always inputs.

Decision: The value of each setting a rule or a return format names is written beside its name where it is named, and the work's worktree, branch and main are the conditional input `work:<id>`, instead of a conditional input for each setting and the worktree's sentences in every round, because a setting is read with what names it, a heading for each short value cost more than the value, and the worktree does not change within a work.

Decision: A conditional input that is not a text is written as compact JSON, with no fences and no indentation, and the return formats write their schemas without `additionalProperties: false`, saying once that no object holds fields it does not list, because the headings already delimit each input and the indentation and the repeated keyword spent tokens on nothing the agent needs.

Decision: Whether a session holds a conditional input is decided by the engine as it runs, from the record of what that session was given and handed back since its last compaction, by content: an input identical to one it was given or to a value of its own returns is held, and after a compaction it holds nothing, instead of the compiler working out statically which inputs a session holds, because a static answer has to hold on every way to a cell, so loops and resumed cells were given the same values again, values read through the database were never held even when the session wrote them, and an input taken as held vanished from the prompt with no pointer to it.

Decision: Every conditional input is given under the one rule, wherever it comes from: when the session does not hold it, as in a new session, one started afresh when its context grew full, or another line's session, it is given, and when it does, it is referred to by its address; a conditional input with nothing in it is not written at all, because a session needs each thing once, whenever it does not have it, and a rule that depends on where an input comes from or on the start of a session fails as soon as a session is started afresh midway.

Decision: A value a round produced is addressed by the round, the cell and the field path as the flow writes it, joined by middle dots, such as round 39, cell 4, end.test_changes[added], its version being the round; every message starts with its own round's address, so an agent's own return sits in its context under that heading; the other conditional inputs are rule:, config:, item:, design_card:, ask: (an ask of the owner), ij: (an interjection) and work: with a name or id, format:common, and format: and inputs: with a cell, and what the engine computes carries the round it computed it for; identical content is one conditional input, addressed by the earliest round that produced it, and the always inputs name a concrete address, never the latest of anything, instead of inputs named by descriptions written for people, because an address points to one version the agent can find in its context.

Decision: The work's history is given to no cell; a cell called in from another line is given the outputs of the engineer's line it needs as named inputs, and an engine step's output reaches agents only as a conditional input of the cells the flow says read it, instead of the history, because the history re-sent every round's whole record each round, descriptions written for people included, and carried engine steps' inputs, which never belong in an agent's context.

Decision: The locked acceptance is addressed by the round that locked it (the design's acceptance, or the advisor's new acceptance), so a cell that reads it through the database and the design round that wrote it share one conditional input; the gate that locks it reads the design's acceptance it is about to lock, because the locked text is that round's own value, and two addresses for one content would give it twice.

Decision: The index of the database (each table and view with the first line of what it holds) and the query that reads one in full are in the query tool's description, which the compiler writes from `db/schema.sql`, so they come with the return formats once in a session, instead of a conditional input of their own or the whole schema with its comments, because an agent reads them where it learns to ask for the tool, a round reads a few tables, and a definition with its comments is one query away.

Decision: The forms every agent's return shares (asking, tools, pausing, answers, redirect, side reports, progress) are one conditional input holding every tool and role any cell has, and each cell's own answer is another, which also says which shared forms the cell has; both are given once in a session for each flow version, with the value of each setting they name (such as the owner's language) written beside it, and the always inputs name the format to hand in, while the command line keeps its one structured-output envelope and the engine checks each return against the cell's whole schema, instead of each cell's whole return schema in every round, because the shared forms are most of every schema and do not change within a flow version.

Rejected:
- Working out at compile time which inputs a session already holds: rejected because a static answer must hold on every way to a cell, so it is too conservative for loops and resumed cells, cannot see what was read through the database, and drops a held input from the prompt without saying where it is, while the record of each session says exactly what it was given.
- Giving the work's history to the cells called in from other lines: rejected because it repeats every round's whole record in every round instead of the outputs a cell needs, and puts engine steps' inputs in an agent's context.
- One address for each source an input reads, such as the database view the acceptance is read through: rejected because one content then has several addresses, and a session that wrote a value is given it again under another name.
- Giving a conditional input by where it comes from (written by the session's own line, needed from the start, from outside): rejected because a session started afresh midway, or another line's session, holds none of them, so each is given by whether the session holds it, whatever its origin.
- Giving the whole message again after a return sent back, with the reason added: rejected because it repeats the task to an agent that did it, and spends a round's worth of tokens to say that one return was written wrongly.
- A notation of the return formats other than JSON Schema, such as types written as code: rejected for now because the descriptions, which are the flow's own words, are three quarters of the formats, and a second notation of the schema the engine checks against could say something the schema does not.
