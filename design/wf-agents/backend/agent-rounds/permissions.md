- agent 的命令只拒绝两类：编译、测试这类占主机 CPU 的重活 (backend/agent-rounds/permissions.md,
  "agent 的命令权限拒绝编译、测试这类重活")，和写到 worktree 以外的，比如推送；其余都放行，执行、写入、联网在内。
  worktree 是它自己的，在里面做的事不会改别人的工作；它够得到 worktree 之外的东西，由引擎自己的防护守住
  (backend/engine.md, "引擎的 git 不运行任何由 agent 可写的配置所指定的程序")。被拒的命令，比如格式化、
  重新生成文件、更新 lock 文件，都得绕到引擎去做，每次多一轮，改了接口类型的条目还会停下来等人。

- 评判设计或改动的 agent 要读到依赖实际做什么，而不是推测，或把问题抛给架构师（第 2 条），所以它自己取来依赖的源码读。

- agent 的命令权限拒绝编译、测试这类重活，否则 agent 可能图方便在本地跑。

- 每一轮里，agent 都能读取数据目录中的工具输出和日志，但不能用它的编辑工具修改它们。引擎把这些路径交给它，否则它打不开。
  shell 命令仍然可以移动或删除它们，这是一个已知缺口。
