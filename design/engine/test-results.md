Decision: The fast CI runs every test of a job to its end, whatever fails before it (`--no-fail-fast` of cargo-nextest), and builds in a step of its own, named `Build`, before the tests run in another, named `Test`, and the ci and ci_before tools give the agent, for each test it named, one result read from the line cargo-nextest writes as each test ends in the logs of every job of that run, the jobs that each run a part of the tests included, and from the steps of the jobs: passed with its own time, failed with how it ended, or not run with the reason (the build failed, a step before the tests failed or was cut off, the run stopped at an earlier failed test, as the CI of code from before this decision still does, a job was cancelled or timed out before the test, no test has that name, or the logs could not be read), and never passed for a test with no line; ci_before differs from ci only in the code it runs the fast CI on, the code before the change with the tests' files put on it; instead of stopping each job at its first failed test, because the tests not yet started then have no line in any log and a test that must fail before the change is the very one an earlier failure cancels, and because the build is a step of its own so that the engine tells from the steps of a job a build that failed from tests that were not run, which the engine reads by the names `Build` and `Test`, a coupling between the workflow and the engine that tests which read the workflow keep, and because nextest runs each test on its own and times it, while the time of the whole test binary that holds a test, all `cargo test` gives, says nothing about the one test; a fast CI that runs its tests another way gives the agent no results; provisional: that a test shows in the log of one job only and that a failed `Build` leaves `Test` unrun are read from the workflow and from past runs, and a red run of `--no-fail-fast` together with `--partition` has not been seen, reopened when a run of the fast CI after the merge shows otherwise.

Decision: The engine checks the table of tests an engineer hands in against the result the runs recorded for each test, and refuses a table that says otherwise: a test recorded as passed is only green and one recorded as failed only red, a test recorded as not run is, before the change, only cannot_run or not_run, and on the head neither green nor red, as no run shows it either way, and a test that no run named, where the newest run on the head or the newest run before the change records results at all, is refused whatever the table says of it, with the tool to name it in; a run recorded before the tools gave each test a result is checked as before, a test said to be red while every check was green, or green while the log tail of a red check names it, because what the engine accepts as proof of a test's result must be what a run recorded, instead of the checks and the tails of their logs, which say nothing of one test in a job that holds many.

Rejected:

- A workflow of its own for ci_before that runs only the tests it is named: rejected because it repeats the set-up of the fast CI in a second workflow that has to be kept in step with it, needs a configuration key and a refusal for a project or a base without it, and saves only the run of tests nobody named, while the result is read the same way.
- An input on the fast CI workflow that narrows the run when it is given and runs the whole workflow when it is not: rejected because it keeps two modes in one workflow, and the mode that runs the whole workflow is the one that cannot answer.
- Keeping the stop at the first failed test and reading the logs: rejected because a cancelled test has no line in any log, so the reading can say only that it is missing, not whether it was cancelled or does not exist.
- A machine-readable report (JUnit) as the source of each test's result: rejected because in a run that never stops early the line cargo-nextest writes as each test ends gives each test's result, and the reason a test did not run comes from the steps of the jobs, which a report does not hold either; a report adds a reader of XML for nothing the lines lack.
- Checking the table of tests only against the checks and the log tails of the red ones, as before: rejected because a table could then claim a result no run recorded for a test, which is what the check exists to refuse.
