# The design tree on a work's branch

When the design tree on a work's branch has a new version, what a version holds, and the forms the engine holds the tree to.

### decision the-tree-is-a-new-version-where-its-id-differs
The design tree on a work's branch has a new version when its git tree differs from the last version's, whoever changed it: main, in what it brought in, or the work, in a commit of its own.
- replaced: Taking the tree to be as main has it, renewed only when main is merged into the work, was on main; the owner changed it, because an input has changed when its content has, whether on main or in the work.

### decision a-return-is-held-to-the-trees-forms
A return that ends a round of a line changing more than the project's tests, and the check before the merge, hold the work to the tree's forms where its change changes the tree.
- replaced: The check of the tree's forms as a step of each project's CI, run on every push, was on main; the owner changed it, because the engine runs it itself and no project's CI need carry it.
- rejected: an agent proposed a tool the agent asks for, with the same check before the merge; the owner rejected it, because a check at the round's end adds nothing beside the engine's existing send-backs, and the agent need do nothing.
