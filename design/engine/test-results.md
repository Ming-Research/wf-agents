Decision: The fast CI runs every test of a job to its end, whatever fails before it (`--no-fail-fast` of cargo-nextest), and builds in a step of its own before the tests run in another, and the ci and ci_before tools give the agent, for each test it named, one result read from the line cargo-nextest writes as each test ends in the logs of every job of that run, the jobs that each run a part of the tests included, and from the steps of the jobs: passed with its own time, failed with how it ended, or not run with the reason (the build failed, the run stopped at an earlier failed test, as the CI of code from before this decision still does, a job was cancelled or timed out before the test, no test has that name, or the logs could not be read), and never passed for a test with no line; ci_before differs from ci only in the code it runs the fast CI on, the code before the change with the tests' files put on it; instead of stopping each job at its first failed test, because the tests not yet started then have no line in any log and a test that must fail before the change is the very one an earlier failure cancels, and without a time the agent fetched the whole job log to find one, and the time of the whole test binary that holds a test, all `cargo test` gives, says nothing about the one test, while nextest runs each test on its own and times it; a fast CI that runs its tests another way gives the agent no results.

Rejected:

- A workflow of its own for ci_before that runs only the tests it is named: rejected because it repeats the set-up of the fast CI in a second workflow that has to be kept in step with it, needs a configuration key and a refusal for a project or a base without it, and saves only the run of tests nobody named, while the result is read the same way.
- An input on the fast CI workflow that narrows the run when it is given and runs the whole workflow when it is not: rejected because it keeps two modes in one workflow, and the mode that runs the whole workflow is the one that cannot answer.
- Keeping the stop at the first failed test and reading the logs: rejected because a cancelled test has no line in any log, so the reading can say only that it is missing, not whether it was cancelled or does not exist.
- A machine-readable report (JUnit) as the source of each test's result: rejected because in a run that never stops early the line cargo-nextest writes as each test ends gives each test's result, and the reason a test did not run comes from the steps of the jobs, which a report does not hold either; a report adds a reader of XML for nothing the lines lack.
