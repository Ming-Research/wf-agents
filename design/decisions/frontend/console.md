# The console

The items as a tree in columns.

### decision the-tree-is-drawn-on-a-canvas
The console's tree is drawn in WebGL on a canvas, only what is on the screen and the titles from one shared set of
glyphs; what an item opens is HTML.
Why: So that hundreds of items move smoothly as the columns glide, which rests on judgment; measured was that a
texture for each title stalled a frame for up to 150 ms as items came into view, where one shared set of glyphs did
not. What an item opens holds words to select and copy, markdown and answers to type, which only HTML does well.

### decision the-tree-follows-what-depends-on-what
The items stand as one tree along what depends on what: where one item depends on another, the other stands under it,
directly or under an item under it. No second tree is drawn by anything else.
Why: Reading down from an item shows everything it needs, and how far it has got is how far what stands under it has
got. A tree drawn by anything besides would be a second relation to keep in step with the dependencies.

### decision an-item-stands-in-one-place
An item stands whole in one place, under the first by number of the items that depend on it; under each other item
that depends on it, it is only a line that points there.
Why: Shown whole in several places, an item would be counted, read and answered more than once, and each thing has one
place (Article 8).

### decision a-card-that-waits-for-the-owner-is-tinted
A card whose work waits for the owner is tinted in the owner's orange with an edge a deeper shade of it, and has no
glow; it is told by that tint, by its third row, which says where it waits, and by its count of questions, white on red.
A card the owner paused is tinted the same way in grey, and one the engine stopped or at fault in red; only a card
whose work runs glows.
Why: A red fill with rings that breathed round it was turned down by the owner as ugly; the tint is how the console on
`old-main` marked a card in work.

### decision a-paused-work-stands-at-its-first-cell-with-something-to-do
The cell a card names for a work the owner paused is the first in the walk that is neither done nor skipped, as the
page reads the cells' states.
Why: The engine's word for a pause names no cell, and the walk holds a work for a pause at exactly that cell; giving the
pause a cell of its own in the deciding code was turned down for what it would change there, by judgment.
